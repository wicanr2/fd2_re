## 二、判準：什麼算文化保存內容

同時滿足以下三點的段落，屬於本工單要復原的範圍：

1. 描述的是**1995 年原版團隊怎麼做**（工具、限制、取捨、署名），不是本專案完成了多少。
2. 內容不會因為重製進度前進或後退而失效。
3. 刪掉之後，讀者無法從首頁看出這個專案除了重製以外還在保存什麼。

反過來，凡是「某個狀態已達整幀 RGB 相同」「本輪新增」「工作清單有幾個 `[x]`」的
敘述，一律**不要**復原。

## 三、必須復原（A 級）

### A1. AFM 工具署名與紀念段落（原 398–405 行）

專案裡最不可替代的一段。1993 年漢堂程式設計師自製動畫工具的署名，是在逆向動畫
資料時挖出來的，原始碼與說明書都已不存在，這行字目前只留在遊戲檔案與本專案裡。

要保留的要素：小節標題「為台灣留一份技術紀念」、引用區塊
`AFM — Animation File Manager Version 1.00　Copyright (C) 1993 Lo Yuan Tsung`、
以及後面那句「把破解出的每一項技術都整理成保存品質的文件，記錄 1995 年台灣團隊
怎麼做一款 DOS 遊戲」，加上 `04`／`05`／`06`／`07` 四個知識庫連結。

放在「專案核心」之後、「已建立的主要貢獻」之前。

### A2. 1995 年總覽入口（原 407–410 行）

目前 README 只把 `15-how-fd2-was-made-1995.md` 當成「專案核心」段落裡的 inline
連結，讀者不會知道那是整個保存線的總結。復原成獨立段落，並保留原本那句說明：
把工具鏈、資料架構、畫面／動畫／音樂／中文／規則／AI 綜合成一支台灣團隊在 DOS 上
做戰棋 RPG 的完整紀錄。

### A3. 開場動畫的繪圖位元組碼虛擬機（原 478–496 行）

這段講的是 1993 年的工程取捨，不是重製進度：開場過場不是逐幀點陣圖，而是一台
10 個運算碼的增量繪圖虛擬機，每幀是一小段位元組碼，對上一幀殘留畫面做疊加而不
清空重畫；96 幀的金鎖動畫因此只要約 1 MB，而不是 96×64000 的全幀陣列。

保留原有的幀／指令格式方塊、派發器 `0x36c9e`、跳表 `0x5276a`、播放器
`0x020421(index, delayMs, skippable)` 與 `0x3dc9f` 開機測速忙等校準的說明，以及
`39-ani-afm-format.md` 連結。純 Go 移植（`remake/internal/afm/`）那句可以留，但要
維持「引擎不夾帶任何版權畫格」的表述。

### A4. 兩種音源與玩家記憶中的聲音（原 498–511 行）

同一首曲子在不同音效卡上是不同聲音，這件事本身就是那個年代的聽覺文化。要保留：

- 曲號溯源方式（`play_bgm` `0x25977` 的 32 處呼叫逐一反組譯，不靠聽曲風猜），
  以及推翻兩個舊推定這件事。
- Roland MT-32 與 Sound Blaster／AdLib 兩條路線；AdLib 用的是遊戲自帶的
  `SAMPLE.AD` 音色庫，那是原版出廠預設音效卡，也是多數玩家記憶中的聲音。
- 兩套都由玩家自備原版檔案在本機渲染，音色庫與 ROM 不隨倉庫散布。

連結 `12-music-playback-and-scene.md` 與 `16-audio-synthesis-soundfont-mt32.md`。

### A5. DOS 上的中文是怎麼做出來的（原 377–385 行）

目前 README 的「繁體中文文字系統還原」只寫了成果，沒寫當年的限制。要補回前提：
DOS 原生不顯示中文，漢堂的做法是自帶一套點陣字型加上用內部索引存文本；`FDTXT`
是 uint16 字模索引序列而非 Big5，共 1016 條字串約 5.8 萬字；`FDOTHER` 資源 #4 是
1824 個 16×16 1bpp 字模，索引 0–35 是數字英文，其後為漢字。

保留 `docs/figures/font_atlas.png` 字模表與 `docs/figures/dialogue.png`，後者仍要
沿用舊 README 的標註慣例，註明是文字／字型解碼研究圖，不是重製執行期截圖。

### A6. 知識庫索引與它的保存定位（原 412–447 行）

目前 README 的「文件導航」只列 6 份現況文件，等於把知識庫呈現成工程佇列。要補回
分類索引（資產格式／遊戲邏輯與機制／引擎控制流／參考與規劃），以及那句定位：
`04`–`11` 同時是「1995 年台灣怎麼做遊戲」的技術保存紀錄。

索引可以精簡條目數，但不能只剩現況文件。新增的 `39`、`50` 等後續專題可一併列入。

### A7. 專案定位語句（原 299、327–329、335–338 行）

三處被刪掉的定位句要以某種形式回到首頁：

- 為 1995 年的台灣遊戲留下可重現的技術紀錄。
- 《炎龍騎士團 2》是 1990 年代華文單機 SRPG 的代表作之一。
- 用第一性原理還原規則與素材，原版程式與素材受著作權保護、不包含在本倉庫。

第三點目前已有等價敘述，前兩點沒有。

## 五、明確不要做的事

1. 不要把 README 整檔還原成 `801c441^`。舊版第 17–228 行的進度流水帳不再回來。
2. 不要動工作區已暫存的兩處修訂（「已閉合的戰鬥規則切片」措辭、含 Xvfb 與資源上限

3. 不要修改 `AGENTS.md`、`docs/`、`tools/`、`remake/` 或任何反組譯成果。第六節的
   AGENTS.md 草稿要等使用者確認才可套用。
4. 復原的文化段落不得夾帶完成度宣稱。凡是提到重製端狀態的句子，維持現有的
   失敗即關閉語氣與證據分級標註。
5. 圖片一律沿用舊 README 的標註慣例：是研究產物、原版擷取、還是重製執行期畫面，
   要在圖說裡寫清楚。
6. 繁體中文，避免中英混雜；不要加「本節說明」「給非技術讀者」這類自我描述標籤。

## 六、給使用者確認：AGENTS.md 建議修改

Codex 會刪掉這些內容不是失誤，是照著規則做的。目前 `AGENTS.md` 有兩個地方直接
導致這個結果：

- 「專案目標與範圍」（第 18–28 行）只定義反向工程、潔淨室重製與證據紀律，沒有
  任何一條說本專案同時是文化保存專案。對照這份清單，AFM 署名和 1993 年的壓縮
  取捨都不屬於目標，是可刪的敘事。
- 「現況資料的權威順序」（第 45 行）把 README 定義成「面向使用者的目前進度與已驗證
  截圖」。README 被定位成進度看板，精簡時第一個被砍的當然是與進度無關的段落。

建議在「專案目標與範圍」補一條：

> - 本專案同時是文化保存專案。1995 年原版團隊的工具鏈、自製格式、開發取捨與作者
>   署名，與重製進度同等重要；這類內容不因與目前進度無關而刪除。

在「現況資料的權威順序」把第 1 條改成：

> 1. `README.md`：面向使用者的專案定位、技術保存紀錄與目前進度。進度敘述以連結
>    指向現況文件，保存與紀念性內容則長期留在首頁。

在「協作與提交」補一條：

> - 精簡或重寫文件時，只能刪除過時斷言、重複內容與應由現況文件承載的進度流水帳。
>   技術保存與紀念性內容（原版工具署名、當年開發手法、格式考證敘事、方法論）不得
>   以篇幅為由刪除；確有必要移出首頁時，必須先搬到知識庫並在 README 留下入口。
