# FD2 全檔位元組一致反編譯

使用者於2026-10-08要求完成全檔匹配，並確認遊戲邏輯還原成 C；原作組合語言與第三方函式庫可保留，覆蓋分開記錄。

使用者已將本目標設為持續 Goal，並授權每輪有經驗證成果後提交與推送。局部成果不縮小目標；完整條件尚未通過時保持 Goal active 與 #198 開啟。

## 固定輸入

| 欄位 | 值 |
|---|---|
| 執行檔 | `FD2.EXE` |
| 大小 | 357074 bytes |
| MD5 | `b97caf2239a27a896069d03549d96e1e` |
| SHA-256 | `222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f` |
| 版本入口 | [`fd2-reference-files.json`](../data/fd2-reference-files.json) |

## 完成條件

- 從受版控的重建來源及明示的本機依賴，在 Docker 內乾淨建置完整 `FD2.EXE`。
- 全檔大小及 SHA-256 與固定輸入相同。不得遮蔽任何 header、重定位、排列或 padding 差異。
- 遊戲邏輯的 C 函式逐一通過產碼比對，保留原始位址、函式名稱、依賴與證據等級。
- 原作組語、第三方函式庫、未分類區間與資料分別記錄。未知區間不能批次升格成原作組語或函式庫。
- 複製原版 EXE 或把未還原的遊戲機器碼原樣放回去，不增加 C 還原覆蓋，也不能單獨結案。
- 重建檔由正式 dosgolem 原版入口抽樣啟動；此驗證沿用 [`tools/dosgolem_oracle.sh`](../../tools/dosgolem_oracle.sh)，不建立第二個 FD2 原版執行器。
- 重建來源供後續原版規則及重製對拍使用；正式 Go／Ebiten 行為仍依既有證據與規格閘門接線。

## 工作順序

1. 沿用[三函式試驗](../data/ida/fd2_matching_pilot_20261008.json)，先以本機已保存的歷史 Watcom 編譯器重跑。
2. 確認可匹配的編譯器候選、旗標、呼叫慣例、型別與編譯單元布局。局部匹配不單獨證明原作精確版本。
3. 建立全檔區間及來源分類台帳，涵蓋 MZ、LE、程式碼、資料、重定位與尾端。
4. 先建立可重跑的組合與全檔差異檢查，再逐函式以 C 替換遊戲邏輯。
5. 檢查剩餘未知、乾淨重建、全檔雜湊及正式執行抽樣，完成後才宣稱全檔匹配。

## 工具與資料邊界

- 原版、歷史編譯器與函式庫唯讀掛載。所有輸出保存在既有 `work/` 研究工作區。
- 歷史工具的公開紀錄只保存版本、雜湊、介面與自行重建來源。私人保存庫的原廠原始碼、工具二進位及函式庫不加入公開儲存庫。
- 含原版或保留函式庫的完整重建檔只在本機驗證。公開發行不在本目標範圍。
- 原始位址及語意證據仍依 [`58`](../knowledge-base/58-fd2-exe-re-coverage.md)、[`56`](../knowledge-base/56-fd2-remake-sdd.md) 與原始 IDA 匯出；不重開已閉合語意來湊全檔進度。
- 唯一現況入口仍為 [`58`](../knowledge-base/58-fd2-exe-re-coverage.md)。本檔保存目標與已確認範圍，不累積逐輪結果。
