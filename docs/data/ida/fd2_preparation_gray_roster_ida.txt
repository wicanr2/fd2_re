## 直接證據

### `0x1088D` 與 `0x11019`

- `0x1088D` 先將 `dword_53BDF` 清為0，再依 persistent record 的原始順序
  逐筆處理。
- 有效記錄以 raw `record+7` 呼叫 `sub_11019`，回傳的 first-seen
  FDICON 快取槽寫入 runtime `record+2`。
- `0x11019` 對已見 raw key 回傳原槽；新 key 才附加十二個圖像指標。
  因此快取槽是首次出現順序，不是角色 ID 或 raw key 本身。

### `0x31E80..0x32002`

- `0x31FBB..0x31FC9` 以 `dword_53A61[(esi * 12) + cycle + 12]` 取得名冊圖像。
  `+12` 表示從快取槽1開始，略過固定隊長所佔的槽0。
- 固定晚期槽的29筆 persistent record 共有29個不重複 raw `+7` key；
  所以這份輸入上的快取槽1..28與除隊長外的 persistent 順序完全一致。
  這個特性不可外推到含重複 raw key 的其他輸入。
- 未選角色由 `0x4DE56` 消費。該函式的直接指令保留四種壓縮模式：
  mode 0 寫入 `(value & 7) + 0x18` 的連續跑，mode 1 交錯寫入，
  mode 2 寫入 literal，mode 3 只前進目的位置。

## 勘誤與重開條件

舊旁車將整張圖的最低差異誤當成名冊比對，宣稱剩餘差異集中於
「selector、RLE 或調色盤」。逐格 `AE=0` 直接否定該說法；真正原因是
固定相位截圖入口在擷取前仍讓 BIOS 近似時鐘推進圖像相位。
重製正式角色選擇器與 `0x4DE56` 不因此修改；只有固定雜湊的證據擷取
入口會凍結明確指定的合法相位。若新輸入有重複 raw key、直接指令反證
`+12` 基準，或同狀態逐格不再相等，才重開本題。
