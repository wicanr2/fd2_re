分類
----

| 家族 | 邊界 | 絕對游標 `[0x53AB1/0x53AB5]` | 鏡頭 `[0x53AA9/0x53AAD]` | 可見游標 `[0x53AB9/0x53ABD]` |
|---|---|---|---|---|
| 鍵盤游標（上／下／右／左）| `0x11B48`／`0x11B9B`／`0x11BFA`／`0x11C59` | ±1 | ±1 或不動 | 不動 或 ±1 |
| 走行步進（下／左／上／右）| `0x12EAA`／`0x1300D`／`0x13185`／`0x13315` | ±1 | `add` 或不動 | 不動 或 ±1 |
| 劇情捲動 | `0x135DD` | ±1 | ±1 | **不寫** |
| 直接設定游標 | `0x149F8..0x14B16` | `mov`／`add` | **不寫** | **不寫** |
| 章節重設 | `0x205DA`、`0x233C6`、`0x235F9`、`0x23E74`、`0x25757` | 設值 | 設值 | 歸零 |
| 開機初始化 | `0x10010..0x10620` | 設值 | 設值 | 設值 |

**沒有任何一處由 `cursor - camera` 重算可見游標。** 因此 `0x135DD` 或
`0x149F8` 搬動游標之後，可見游標會合法地停在舊值。

`0x135DD` 的兩個 `±1` 是**同一格的同一次位移**，不是兩個獨立的量：

```text
0x13606 dec dword_53AB1 / 0x1360C dec dword_53AA9   ; X 軸同減
0x13614 inc dword_53AB1 / 0x1361A inc dword_53AA9   ; X 軸同加
0x1363F dec dword_53AB5 / 0x13645 dec dword_53AAD   ; Y 軸同減
0x1364D inc dword_53AB5 / 0x13653 inc dword_53AAD   ; Y 軸同加
```

每一格之間插一次 `push 0 ; call 0x11CAC` 與 `call 0x4E031`，X 迴圈走完才進
Y 迴圈；進入時 `0x135F2 mov dword_51A83, 0`，返回的共用尾巴 `0x13181` 不還原它。
執行期收據：`docs/data/ui-traces/fd2-story-pan-cursor-20260909.json`。

安全帶規則（兩個家族相同）
--------------------------

以向上為例，`0x11B48` 的直接指令：

```text
0x11B52 cmp dword_53AB5, 0      ; 絕對游標已在最上緣 → 只重繪
0x11B59 je  0x11B90
0x11B5B cmp dword_53ABD, 2      ; 可見游標 >= 2 → 在安全帶內
0x11B62 jge 0x11B7B
0x11B64 cmp dword_53AAD, 0      ; 鏡頭已到頂 → 也只能移可見游標
0x11B6B je  0x11B7B
0x11B6D dec dword_53AB5         ; 否則捲鏡頭：游標與鏡頭同減，可見不動
0x11B73 dec dword_53AAD
0x11B79 jmp 0x11B90
0x11B7B dec dword_53AB5         ; 安全帶內：游標與可見同減，鏡頭不動
0x11B81 dec dword_53ABD
0x11B87 cmp dword_51A83, 0      ; overlay selector 為 0 時略過重繪
0x11B8E je  0x11B9A
0x11B90 push 0 ; call 0x11CAC
```

四個方向的門檻：上 `visible_y >= 2`、下 `visible_y <= 5`、
左 `visible_x >= 2`、右 `visible_x <= 0x0A`；鏡頭端界線分別是
`camera_y == 0`、`camera_y == [0x53AC5] - 8`、`camera_x == 0`、
`camera_x == [0x53AC1] - 0x0D`。視窗是 13×8（同一組常數也出現在
`0x174AE`／`0x174B0` 的 `push 8`／`push 0xD`）。

絕對游標也被夾住，以向下的 `0x11B9B` 為例：

```text
0x11BA5 mov eax, dword_53AC5 ; dec eax
0x11BAB cmp eax, dword_53AB5 ; je 0x11BEF   ; 已在場地最下緣 → 只重繪
0x11BBC mov eax, dword_53AC5 ; sub eax, 8
0x11BC4 cmp eax, dword_53AAD ; je 0x11BDA   ; 鏡頭已到底
```

**只有可見游標沒有界線**：它在八個寫入端裡一律是 `inc`／`dec`／`mov`，
沒有任何一處比對範圍。因此鏡頭與絕對游標的界線是原版契約，可見游標的
13×8 只是消費端（`0x1741C`）的要求。

走行步進以 `0x13185`（上）為例，同一分支結構：捲鏡頭時走
`0x13304 add dword_53AAD, eax`，否則 `0x13205 dec dword_53ABD`；
絕對游標一定由 `0x1330A dec dword_53AB5` 跟著單位走。

可見游標的消費端
----------------

`0x1741C`（指令環展開）在 `0x1743F..0x1746A` 用它算出畫面位址：

```text
0x1743F imul edx, dword_53AB9, 0x18        ; visible_x * 24
0x1744E mov  edx, dword_53ABD              ; visible_y
0x17454..0x17468                            ; edx * 10944 (= 24 * 0x1C8)
0x1744B lea  edi, [eax + edx]              ; [0x53A49] + 0x8088 + …
```

也就是「可見游標＝視窗內的格座標」，直接乘 24 與 24×456 得到 framebuffer
位移。這是已證實的語意，不是命名推測。
