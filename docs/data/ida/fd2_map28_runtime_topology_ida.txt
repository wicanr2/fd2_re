Constructor frontier (confirmed)
--------------------------------
sub_1088D loads the chapter resources and constructs the persistent party.
At 0x10B3C it pushes group 0 and calls sub_10B4E at 0x10B3E.  Map28 has no
group-0 constructor row, so LOADCH leaves the 20 persistent party records.

raw ch28 pre-handler sub_33DBA calls LOADCH, then at 0x33E10..0x33E16 passes
(group=8,x=9,y=19) through sub_35822.  sub_35822 performs pan, calls
sub_10B4E(group), then runs its palette/presentation tail.  Group8 contributes
56 records.  Therefore the normal pre-handler-to-battle handoff has exactly
20+56=76 current runtime records, ordered persistent party first and group8
second.  This is the confirmed base frontier; it is not the 76-row raw source
table rebuilt as a normalized all-groups battle.

Dynamic event chain (confirmed mutations; player reachability of the trigger

Field event75 sub_35C79, on its runtime-record +8 == 9 branch, writes current
context byte +11=1, schedules turn-control row1 for current round+1, writes
current context byte +10=4, and schedules row0 for the current round.

Turn event74 sub_35C32 reads current context byte +10 and passes it as group to

Turn event76 sub_35D60 advances context byte +11 while it is not 4 and

Turn event79 sub_35EE6 reschedules row2 and uses context +15 plus a modulo-3
choice to operate on two members of the already appended group1.  It does not
