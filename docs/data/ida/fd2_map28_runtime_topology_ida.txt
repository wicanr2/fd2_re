Constructor frontier (confirmed)
--------------------------------
sub_1088D loads the chapter resources and constructs the persistent party.
At 0x10B3C it pushes group 0 and calls sub_10B4E at 0x10B3E.  Map28 has no
group-0 constructor row, so LOADCH leaves the 20 persistent party records.

raw ch28 pre-handler sub_33DBA calls LOADCH, then at 0x33E10..0x33E16 passes
(group=8,x=9,y=19) through sub_35822.  sub_35822 performs pan, calls
sub_10B4E(group), then runs its palette/presentation tail.  Group8 contributes
56 records.  Therefore the normal pre-handler-to-battle handoff has exactly
20+56=76 current runtime records, ordered persistent party first and group8
second.  This is the confirmed base frontier; it is not the 76-row raw source
table rebuilt as a normalized all-groups battle.

## event75／event74 精確指令補證（2026-08-21）

輸入仍為本檔檔首所列 `FD2.EXE` 雜湊；工具為 IDA Pro 9.4，位址均為 IDA
資料庫線性位址。以下語意等級均為「已證實」，但語意名稱只供導覽，原始
`sub_*` 名稱與位址保留不變。

- map28 實際地圖大小為 31×64；`native_field_event_slots` 的唯一非負格為
  `(15,21)`、slot 1。曾以錯誤寬度 29 暫算出的 `(28,22)` 無效，不得引用。
- `sub_35C79`（`0x35C79..0x35D60`，event75）先檢查觸發單位 record `+6`
  非零、`[[0x53AD5]+0x11] == 0` 與 record `+8`。`+8 != 9` 時先把觸發
  record `+7` 交給 `0x1956B`，再消費 FDTXT_029 index 0；`+8 == 9` 時消費
  index 1，然後寫 event-state
  `[0x11]=1`、`[0x10]=4`，把 live row 1（event76/raw camp 2）排到
  `native_round+1`，並把 live row 0（event74/raw camp 0）排到目前 round。
- `sub_35C32`（`0x35C32..0x35C79`，event74）在 `0x35C4A` 把
  event-state `[0x10]` 作為 group，呼叫 `0x35822(group,10,29)`。group 不是
  7 時把 live row 0 排到 `native_round+1`；共同尾端 `0x35992` 將
  event-state `[0x10]` 加一。因此 event75 的 seed 4 只會依次 materialize
  groups 4、5、6、7。

### 可編輯資料與執行期契約

1. event75 必須是 selector 1 的欄位事件規則；只有成功動作的共同提交點可

## event76 精確指令與 phase 契約（2026-08-21）

輸入雜湊、IDA 版本與線性位址基準同上；下列均為「已證實」。

- `sub_35D60`（`0x35D60..0x35E5A`）讀 event-state `[0x11]`。值不是4時，
  呼叫 `0x13512(1)`，將 runtime record slot1 的 raw `+5` bit7 設為1；再把
  `[0x11]` 加一，並將 live row1（event76/raw camp2）排到
  `native_round+1`。
- 值等於4時，先消費 FDTXT_029 index2，再呼叫 `0x10B4E(group1)`。依
  [`fd2_future_group_raw_gate_ida.txt`](../fd2_future_group_raw_gate_ida.txt)，
  `[0x53AFA]` 只有已列的直接 writers；本 caller 與其 event76 路徑都不寫，
  所以此處具證據的 `raw_placement_gate` 為0。group1固定三筆，函式把
  `runtime_count-3` 寫入 event-state `[0x15]`，並把 live row2
  （event79/raw camp0）排到目前 native round。
- 後續演出順序是 `0x35E5A` palette pulse、400ms delay、第二次 pulse、
  400ms delay，接著對 FDTXT_029 indices3、4、5、6各執行一次
  `pulse → dialogue`。這六次 pulse 都是同一個已閉合的127-step indexed DAC
  presenter，不可改成 RGBA fade 或純 delay。
- 原始 `0x1A30B` 的 phase order 是 selector1、目前 round 的 raw camp0、round
  increment、再 dispatch raw camp2。因此重製端 event76 owner 必須在敵方回合
  完成並增加 `NativeRoundCounter` 後、玩家重新取得輸入前執行；不得降成一般
  `on_turn_end` action，也不得在 raw camp0 前提早執行。

### event76 可編輯資料與執行期契約

1. typed rule 必須保存 handler `0x35D60`、state index17、repeat limit4、
   `0x13512(slot1)`、row1 reschedule delta1，以及 final branch 的 text index2、
   group1／gate0／count3、base state index21、row2 event79/raw camp0/current round。
2. repeat branch 必須先驗證 slot1 raw `+5` provenance、live row1 identity、state

3. final branch 必須在 index2 對話完成後，先於私有 battle-state clone 完整建構
   group1與row2/base state，再一次發布；任一 constructor、position、selector或
   row驗證失敗時不得留下部分 group。
4. 六次 pulse、兩次額外400ms與 indices3..6 對話全部完成後，才能把輸入交回
