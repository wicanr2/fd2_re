# FD2 故事對話框、斷行與翻頁證據

## 版本與工具

- 輸入：`FD2.EXE`，357074 bytes。
- MD5：`b97caf2239a27a896069d03549d96e1e`。
- SHA-256：`222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`。
- 第一工具：使用者授權的 IDA Pro 9.4／Hex-Rays，映像
  `fd2-ida-authorized-local:latest`，DOS LE loader 的 IDA linear address。
- 交叉驗證：`fd2-cap-local:latest`／Capstone；原始執行檔唯讀，資料庫只在
  `/tmp/fd2-dialogue-layout-ida` 的一次性工作目錄建立。
- 本文件採非破壞性註記：`sub_15F84`、`sub_165AC`、`sub_1685C`、
  `sub_168B6`、`sub_16B43`、`sub_16C57` 與所有原始位址均保留。

## 已證實：故事開框 consumer 與原生座標

IDA 對 `sub_165AC` 的直接交叉參照只有 `0x161D7` 與 `0x162BC`，兩者都在
`sub_15F84` 的 `FFEF(-17)`／`FFEE(-18)` 分支；`FFED(-19)`／`FFEC(-20)`
則經共享尾段跳回同兩個 call。四條路徑因此共同消費同一開框 compositor，
不是可任意套用到其他 UI 的泛用「縮放框」名稱。

`sub_15F84` 的直接指令固定：

- `0x16174`：上框 portrait destination `0x728`；`0x161D7` 呼叫
  `sub_165AC(record[0], record[1], 2)`；`0x16218/0x16220` 把文字目的位址設成
  `0xA0B4F`，相對 VGA `0xB4F = (15,9)`。
- `0x1625E`：下框 portrait destination `0x9017`；`0x162BC` 呼叫
  `sub_165AC(record[0], record[1], 112)`；`0x162FD/0x16305` 把文字目的位址設成
  `0xA951F`，相對 VGA `0x951F = (95,119)`。
- `0x16397..0x163DC` 與 `0x16413..0x16458` 證實 `FFED/FFEC` 以
  `operand*0x50 + [0x53A45]` 取得 runtime record，再取 record `+7` 載入 DATO；
  不可把 operand 當固定肖像 ID。
- 四分支都把原始 record 前兩個 bytes 傳給 `sub_165AC`，並以
  `0x4E8AF`（上）／`0x4E8E1`（下）貼頭像。這兩個 record bytes 的高階語意
  本輪仍是未知，不建立猜測名稱。

`sub_165AC` 的最後一幀依序執行：

```text
sub_4E96F(save=310×86, source=VGA+320*y+5, stride=320)
sub_168B6(VGA, 320, 5, y, 4,2)
sub_168B6(VGA, 320, 5, y, 8,3)
sub_168B6(VGA, 320, 5, y,12,4)
sub_168B6(VGA, 320, 5, y,16,5)
sub_168B6(VGA, 320, 5, y,19,5)
```

`y` 由 caller／`[0x53C67]` 固定為上框 `2` 或下框 `112`。`sub_168B6`
逐格以 `sub_1685C` 從 `[0x53A81]`（FDOTHER #5）貼 index 1..17，再以 index 13
填滿內部；最終參數是 `x=5, y=2/112, columns=19, rows=5`。這是**已證實**的
故事框格座標；舊文件把 `[0x53AB9]/[0x53ABD]` 命名成框寬高的說法仍維持撤回，
因為它們只參與開框前相機／游標相對過場，不決定上述最終框格。

## 已證實：`FFFE`／`FFFD` 的 consumer

- `0x1630D` 讀下一個 signed uint16 word。
- `0x16319..0x16365`：`FFFE(-2)` 只增加行號，目的位址為
  `base + line*19*320`；若故事框已在第3行又換行，`0x16341` 呼叫
  `sub_16E24` 後把行號減一，形成三行窗口捲動。
- `0x15FC4..0x16044`：`FFFD(-3)` 先採相同換行／三行窗口規則，再於
  `0x16034` 呼叫 `sub_16C57(1)`，等待輸入並清理／更新框內頁面。
- 普通 glyph 在 `0x1645F..0x1647F` 呼叫 `sub_4EA2A`，之後目的位址加16。
  `ch24_post` caller 已證實傳入 style `foreground=0xCD, shadow=0x4C,
  background=0x4A`、`stride=320`、`line_step=19`。

Capstone 原始 bytes 視窗至少保存以下回查錨點：

## ch24_post index 6／7 可編輯投影

原始 `FDTXT_025.bin`：3350 bytes；MD5
`5ecbe03ee3be4654fcfa638bf0dbfd4e`；SHA-256
`d8bba8eb5f2f0a52a3dd237d6dc308b3e932af577c43b818409fa63bca89433a`。
本輪以 raw uint16 words 逐句切分，保留四種開框碼、operand、`FFFE` 與 `FFFD`。

- index6：7句；每句 page 數依序 `2,2,2,1,1,3,1`。
- index7：11句；每句 page 數依序 `1,1,1,1,2,1,3,1,2,1,1`。
- 每頁最多3列；每列原始可見 glyph 最多13個，後續列含原版全形空白。
- index6 utterance0、2、5 的 `FFED operand=16` 是 runtime slot；其他
  `FFED` 同理。index7 的 `FFEF operand=29/16` 與 `FFEE operand=0/21/4`
  仍保留原始 identity lookup operand，不把它命名成 DATO selector。

證據分級：raw words、控制碼次序、頁／列切分、caller 實參及上述 compositor
座標均為**已證實**。把可編輯 Unicode 列重新映射到同一 FDOTHER glyph index，
屬 remake 的 typed data 投影；未知字元、超過3列的 page、與原始 control／operand
不一致時必須失敗即關閉。逐字發布、嘴型、開／關框中間幀與未修改 DOS 一般玩家
畫面比較仍未完成，不得由穩定頁面 renderer 升格為 E2。

## 2026-08-25 勘誤：逐字發布的已證實邊界

上一段把「逐字發布」整體列為未完成，容易把原版證據與重製消費端混為一談。
`0x1645F..0x1647F` 已直接證實：每個普通 glyph 都先呼叫 `sub_4EA2A` 寫入目前
VGA 目的位址，才把目的位址加16並讀下一個 word；`FFFE` 只改行號／目的位址，
`FFFD` 則在既有內容後進入輸入與頁面更新。故下列窄契約為**已證實**：

- 同一頁的可見字形依 raw word 次序、逐列由左至右發布；
- `FFFE` 本身不新增可見 glyph；
- page 的所有普通 glyph 完成前，caller 尚未返回到外層下一句處理。

這項證據足以讓 ch24 index6／7 的 typed pages 建立「每新增一個 glyph 的 indexed
frame」正式消費端。它仍不證明每個 frame 的 DOS wall-clock、Ebiten 應重複幾個
更新週期、嘴型 frame、`sub_165AC／sub_16B43` 全部開關框中間畫面或一般玩家 E2；
這些限制不得由逐字順序外推。

## 2026-08-25：`sub_165AC` 五階段開框的可消費邊界

本文件前段已保存 `sub_165AC` 的五次直接 `sub_168B6` 呼叫：`(4,2)`、`(8,3)`、
`(12,4)`、`(16,5)`、`(19,5)`，共同使用 caller 的 `(x=5,y=2/112)`、stride320
與 FDOTHER #5。這五組 columns／rows 及順序為**已證實**；每一階段以同一保存的
VGA source 建立格網，最後一階段等於既有穩定頁的完整19×5框。

ch24 caller 可據此發布五張無文字的 indexed opening frames，之後才進入既有
portrait＋逐字序列。Ebiten 如何把五張來源幀分配到60 Hz更新仍只是重製近似；
`sub_16B43` closing、portrait 在每個開框中間階段是否可見及嘴型仍未由本段提升，
不得反向播放 opening 冒充 closing。

## 2026-08-25 勘誤：`sub_16B43` 保存畫面的收框與可選移動尾段

前段把 `sub_16B43` 整體列為未知已被本輪 IDA 直接指令與 Capstone 原始 bytes
推翻。輸入、雜湊、工具與位址空間同本文件「版本與工具」；本輪一次性 IDA
資料庫只寫入 `/tmp/fd2-ch24-closing-ida`，沒有改名或覆寫原始定位。

`sub_15F84` 對 `sub_16B43` 只有五個直接呼叫：`0x1616C`、`0x16256`、
`0x1638F`、`0x1640B`、`0x164CF`。每一處都先呼叫 `sub_16559(0)` 與
`sub_16C57(0)`，再依序傳入 `var_1C`（`sub_165AC` 回傳的五指標陣列）及
`var_20`。這項 caller／consumer 關係為**已證實**。

`sub_165AC` 在每次擴框前各保存一張 `310×86`、stride320 的 VGA strip；五張
依序是原背景、4×2後、8×3後、12×4後、16×5後。`sub_16B43` 的
`0x16B54..0x16B9A` 從指標4倒序呼叫 `sub_15E71`，因此實際可見收框狀態固定為：

```text
16×5 → 12×4 → 8×3 → 4×2 → 原背景
```

前四次 restore 後各呼叫 `delay(10)`；最後原背景 restore 後不等待。
`sub_15E71` 直接以 `sub_4E92C(snapshot,VGA,320)` 復原並釋放 snapshot，故這不是
把開框參數猜測性倒播，而是**已證實**的 caller-owned framebuffer snapshot
消費順序。portrait／文字在第一個 restore 即隨 19×5 完整框一併消失。

若 `var_20==0`，`0x16B9D..0x16BA2` 立即返回。非零時另有一段**已證實**的
游標／視圖移動尾段；它不是五張 snapshot 的一部分：

```text
cursorX = 24*[0x53AB9]+4
cursorY = 24*[0x53ABD]+4
total   = [0x53AB9]+[0x53ABD]
for i=0..total:
    x = 5 - trunc((5-cursorX)*i/total)
    y = var_20 - trunc((var_20-cursorY)*i/total)
```

每一步以 FDOTHER #5 LMI directory `word[+6]`（entry0）交給 `sub_15E9E` 疊在
VGA `(x,y)`，`delay(10)` 後由 `sub_15E71` 復原；`total==0` 時直接返回。
`[0x53AB9]/[0x53ABD]` 只沿用既有已證實的 camera-relative visible cursor
X／Y 語意。本段的座標、entry、迴圈邊界及 restore 順序均為**已證實**；60 Hz
應重複幾幀仍只可標成重製近似。

`var_20` writer 亦由 caller 直接指令分開保存：`FFED=2`、`FFEC=112`；
`FFEF/FFEE` 先呼叫 `sub_12C60(operand)`，只有回傳非 `-1` 才分別寫2／112，
否則寫0。重製端不得僅由上／下框、靜態 speaker 或角色名稱猜測查找命中；必須
保留 `0x12C60` 的 runtime identity lookup provenance，無法重建時失敗即關閉。

本輪同一 IDA 9.4 資料庫再核對 `0x12C60..0x12CEA` 與其直接 consumer
`0x3453E..0x34565`：第一張 `[0x53A45]`、count `[0x53BEB]`、stride0x50 的表
以 record `+8` 比對 operand，並且只有 `record[+5]&1==0` 才回傳該索引；第二張
`[0x53BF7]` 即使命中也只保存 pointer，函式仍回傳 `-1`。因此移動尾段的命中
契約可精確縮成「目前已 materialize 第一張 scene-unit array 中，第一筆
`NativeIdentity==operand` 且 raw byte5 bit0 為0的 record」。這兩個函式的原始
名稱、位址與欄位偏移均保留；把 bit0 描述為 active／inactive 只沿用既有 runtime
投影，不取代原始 byte 判斷。

證據等級限制：五張收框、可選尾段公式及四控制碼的 `var_20` writer 已達
**已證實**；ch24 一般玩家同狀態畫面、DOS wall-clock 與 `0x3453E` 額外過濾器
的高階語意仍未知。`0x3453E` 的高階玩法名稱仍不另作推論，但其 `record[+5]&1`
consumer 已閉合。舊的「closing 未知／不得反向播放」警告只保留其歷史原因，
由本勘誤取代，不得再次用來重開相同 RE。
