## 二、caller、函式邊界與唯一直接呼叫

IDA 函式清冊：

```text
sub_240FA  0x240fa..0x24336
sub_24336  0x24336..0x244b6
sub_20421  0x20421..0x205b4
sub_135DD  0x135dd..0x1366a
sub_4DFCC  0x4dfcc..0x4e031
```

`sub_24336` 只有一個直接 caller：`sub_240FA` 的 `0x242C9`。caller 在
物品 `0xD1..0xD6` 對 runtime slots `0..15` 的配對數恰為6時，依序移除、
給予 item `0x64`，播放 FDTXT indices 7／8／9 與 ACT63／64，然後呼叫：

```text
0x242c1  call sub_15F84       ; text index 9
0x242c6  add  esp, 24h
0x242c9  call sub_24336       ; 沒有參數
0x242ce  push 1               ; 下一個 dialog 的第一個 push
...
0x24308  call sub_15F84       ; success index10／failure index6
0x24310  push 18h
0x24312  call sub_112A5       ; JOIN 24
0x2431a  push 17h
0x2431c  call sub_112A5       ; JOIN 23
0x24324  call sub_11506       ; sync party
0x24329  inc  dword_53C03
```

因此 `0x242C9→0x24336` 是 caller-specific 的固定成功分支演出，不是可帶任意
資源／幀範圍的通用腳本 ABI。

## 三、`sub_24336` 的直接指令與排程

### 3.1 鏡頭、基底與 FDOTHER #34

```text
0x24344  push 8
0x24346  push 0Eh
0x24348  call sub_135DD       ; C 參數順序 (14,8)
0x24350  push 0FA00h
0x24355  call malloc
0x24361  push 0FA00h
0x24366  push 0A0000h
0x2436b  push eax
0x2436c  call memmove         ; 保存320×200 VGA基底
0x24374  push 22h
0x24376  push 0
0x24378  push "FDOTHER.DAT"
0x2437d  call sub_111BA       ; resource 34
0x24387  push -1
0x24389  push 140h
0x2438e  push esi
0x2438f  push 0
0x24391  push eax
0x24392  call sub_2935B       ; frame0 疊入保存基底
```

`sub_135DD(14,8)` 的直接指令先逐格變更 X 全域
`[0x53AA9]/[0x53AB1]`，再逐格變更 Y 全域 `[0x53AAD]/[0x53AB5]`；每格均
呼叫 `0x11CAC(0)` 及 `0x4E031`。所以重製端保留 X-first／Y-second、絕對游標與
相機一起移動、visible cursor 不變的契約；不把它縮成一次座標跳轉。

### 3.2 frame 1..68 與色盤循環

```text
0x2439a  mov  esi, 1
0x243a1  ...                  ; 從保存基底複製到工作 framebuffer
0x243c4  call sub_2935B       ; 疊 frame esi，stride320，transparent=-1
0x243dc  call memmove         ; 工作 framebuffer → VGA
0x243e4  call sub_4DFCC
0x243e9  push 3
0x243eb  call sub_17AA9
0x243f3  call sub_4E031
0x243f8  inc  esi
0x243f9  cmp  esi, 45h
0x243fc  jl   0x243a1
```

迴圈因此呈現 frame `1..68`。每幀呼叫 `sub_4DFCC`，再等待三個 BIOS tick
delta 並 present。`sub_4DFCC` 本身的固定直接指令為：

```text
0x4dfce  call sub_4DFC0
0x4dfd3  sub  ax, [0x60000]
0x4dfda  cmp  ax, 2
0x4dfde  jb   0x4e02e
0x4dfe0  inc  byte [0x60002]
0x4dfe6  cmp  byte [0x60002], 10h
0x4dfef  mov  byte [0x60002], 0
0x4dff8  mov  al, byte [0x60002]
0x4dffd  mov  ah, 3
0x4dfff  mul  ah
0x4e001  lea  esi, [0x60003]
0x4e009  mov  ecx, 10h
0x4e00e  mov  ah, 0E0h
0x4e010  mov  dx, 3C8h
...
0x4e021  loop 0x4e010
```

也就是兩 tick 閘門後把程序全域 phase 加一並對16色 DAC entries
`0xE0..0xEF` 寫入由 `0x60003 + 3*phase` 起的重疊 RGB 表。phase 是程序生命週期
狀態，不是 `sub_24336` 的固定零起點；重製端只宣稱保留相對循環，精確首相位仍
需要同程序同狀態動態驗證。

### 3.3 ANI #0、全色盤閃白與停留

```text
0x243fe  push 0
0x24400  push 0Fh
0x24402  push 0
0x24404  call sub_20421       ; ANI #0，15ms，skippable=0
0x2440c  push 3Fh
0x2440e  push 0FFh
0x24413  push 0
0x24415  call sub_11DF2       ; DAC entries 0..255，delta63
0x2441d  push 64h
0x2441f  call delay           ; 100ms
0x24427  push 0
0x24429  push 0FFh
0x2442e  push 0
0x24430  call sub_11DF2       ; 同範圍 delta0
0x24438  push 1F4h
0x2443d  call delay           ; 500ms
```

`sub_20421` 的直接指令開啟 `ANI.DAT`、以 `resource*4+6` 讀 archive offset、
執行每幀 AFM VM、每幀呼叫 `delay(arg4)`；只有 `arg8 != 0` 時才查輸入
`0x10620`。因此本 caller 是 ANI resource0、每幀15ms、不可輸入略過。
`arg0==1` 才會額外載入 FDOTHER #78，本 caller `arg0=0` 不走該分支。

`sub_11DF2` 以 immutable baseline `[0x53A65]` 計算 DAC，不消費 ANI VM 私有
palette buffer；重製端的白閃／baseline restore 因而也以原生地圖 baseline DAC
重新著色當前 ANI 索引畫面。

### 3.4 frame 69..100 與清理

```text
0x24447  ...                  ; 保存基底 → 工作 framebuffer
0x2446a  call sub_2935B       ; 疊 frame esi
0x24482  call memmove         ; 工作 framebuffer → VGA
0x2448a  push 3
0x2448c  call sub_17AA9
0x24494  call sub_4E031
0x24499  inc  esi
0x2449a  cmp  esi, 65h
0x2449d  jl   0x24447
0x2449f  push ebp
0x244a0  call free
0x244a8  push edi
0x244a9  call free
```

前一迴圈離開時 `esi=69`，所以尾段呈現 frame `69..100`；這段沒有
`sub_4DFCC` 色盤循環。兩個配置都釋放後返回共用 epilogue。

## 四、玩家第21戰 runtime 拓撲勘誤

`FDFIELD` resources 60／61／62 對應 map20：41×40、80筆 control rows、
96筆 position records（80筆單位位置加16格部署位置）。control group 分布為：

```text
group0=59, group1=4, group2=4, group3=4, group4=4, group255=5
camp: own=2, ally=8, enemy=70
```

固定資源指紋：

```text
FDFIELD_060 size=6564  md5=3e2525c3cb4087029e910f6be9f9da58
 sha256=da246117eb7c8f9724e69e5e87eb8be4e03c2278439b92cd5ab99f72bd7cee3d
FDFIELD_061 size=2211  md5=8caf6834d9f72e8a865664a7f66bb30b
 sha256=3cc6167f0904e7cb81e9a60090df168d716959ead1381142a3be343a14489d28
FDFIELD_062 size=578   md5=c1e4e939bef0dc23005d5eed64fa2aac
 sha256=7b1402736790351e171e6dcc6f2b8110a418808dccc7978d1d8448a386057705
```

本關正常整備出戰16人，開場再 append group0 的59筆，因此原版 runtime
frontier 是75；回合2／4／6／8依序 append groups1／2／3／4後為
`79→83→87→91`，group255不 materialize。舊重製若先保留全部80筆 FDFIELD rows
再 append party，會得到錯誤 topology。`ch21.json` 現以
`runtime_append_groups:true` 與 `initial_groups:[0]` 明確固定正確建構順序。

## 五、重製消費端與仍未解除的閘門

### 5.1 相鄰 layout／ACT63／64 補證與可審查規格（2026-08-27）

合法 IDA Pro 9.4 重新匯出 `sub_240FA`、`sub_233C6` 與 `sub_1366A`；
`0x2415B` 的 11 個參數按實際 PUSH 逆序解讀為：三張 slots 0..24 的
`x／y／pose` 表、start=0、end=24、special slot=25、special
`(x,y,pose)=(23,14,1)`、camera raw `(14,10)`。三張固定表由
`0x52228／0x52241／0x5225A` 各讀 25 bytes：

```text
x    = 15 14 16 16 13 13 13 13 12 14 14 14 12 15 15 15 15 13 12 16 11 11 11 17 17
y    = 14 14 13 14 14 15 16 17 14 15 16 17 13 15 16 17 11 11 11 11 12 13 14 12 13
pose = 02 02 01 01 02 02 02 02 03 02 02 02 03 02 02 02 00 00 00 00 03 03 03 01 01
```

`sub_233C6` 的直接 consumer 證實 slots 0..24 寫 raw record `+0/+1/+3`，
special slot25 亦寫相同三欄；camera raw 乘既有 24-pixel 格距後是
`(336,240)`。這裡只把原始參數資料化，不替角色或姿態新增高階名稱。

同一 caller 在 `0x24253／0x2428E` 各先把 `dword_51A83` 歸零，再於
`0x2425F` 呼叫 ACTING 63、`0x2429A` 呼叫 ACTING 64。既有完整 acting decoder
的 resource 63／64 分別為 4／5 幀，目標只含 slots 0、16；其 frame beats、
special bit、slot 與 pose 原樣轉入 typed beat。正式順序規格為：

```text
layout → FDTXT_021 #5 → recipe branch
crafted: #7 → ACT63 → #8 → ACT64 → #9 → 0x24336 → #10
common: JOIN24 → JOIN23 → sync party → chapter21 → town_ch22
```

layout 在擺位前驗證全部 slots；ACT beat 在啟動時驗證其 targets；`0x24336`
則在變更鏡頭前預檢原生地圖與全部動畫資產。缺任一階段輸入時失敗即關閉，
不得只播放對話並略過該段演出。證據等級為
`RE-CLOSED／DATA-READY`；正式執行期與玩家路徑仍須以下方回歸驗收。

### 5.2 六個分支對話 tuple 與原生版面規格（2026-08-27）

`sub_240FA` 的直接指令固定五個 `0x15F84` callsite，其中 `0x24308` 的
text index 由成功／不足兩臂在 `0x242E5`／`0x24300` 分別 PUSH 10／6後匯合；
因此共有六個 `(caller,string_index)` tuple。線性 handler 匯出只保留 index6，
不能據此遺失成功臂 index10：

| caller | FDTXT_021 index | utterances | editable mapping |
|---|---:|---:|---|
| `0x24182` | 5 | 10 | scene1 lines7..16 |
| `0x2424B` | 7 | 1 | scene3 line0 |
| `0x24286` | 8 | 3 | scene3 lines1..3 |
| `0x242C1` | 9 | 2 | scene3 lines4..5 |
| `0x24308` | 10 | 10 | scene3 lines6..15（crafted） |
| `0x24308` | 6 | 4 | scene2 lines0..3（insufficient） |

權威來源是固定版 `FDTXT.DAT`（120,502 bytes；MD5
`fe5c487ce4313485f1da9d48d35b05f9`；SHA-256
`a4555f8a0e61e884b4f504d56a8bdde11672583bbbbc6506281ae10dcdfb1f69`）的 archive
第21項，offset `0x10446`、長度4,660 bytes。其內容與
`extracted/raw/FDTXT/FDTXT_021.bin` 逐 byte 相同；該項 MD5
`cf808640b1010adc0682578271611279`、SHA-256
`6bd646e63a07c5ae7fc7fa80295e51fc639cc9a176732784de99e619ba663e78`。
先前工作階段曾出現沒有來源的3,231-byte紀錄；工作區、Git歷史與原始archive
均無此資產，已撤回且不得再引用。

raw control／operand 摘要如下；實際 pages與glyph rows由受版控資料保存：

```text
#5  FFEF/24, FFEE/21, FFEF/24, FFEE/21, FFEF/24,
    FFEE/21, FFEF/24, FFEE/21, FFEF/24, FFEE/21
#6  FFEF/24, FFEF/23, FFEE/21, FFEE/0
#7  FFEE/0
#8  FFEF/24, FFEE/0, FFEF/24
#9  FFEF/24, FFEF/24
#10 FFEE/24, FFEE/21, FFEE/4, FFEE/21, FFEE/0,
    FFEE/21, FFEE/0, FFEF/24, FFEF/23, FFEE/0
```

可審查規格：兩臂共用#5十句；crafted臂依#7→ACT63→#8→ACT64→#9→
`0x24336`→#10，insufficient臂只播放#6。每個既有分組 `dialog` beat必須保存
逐句 `native_dialogues`，數量嚴格等於 `count`；執行期依行序選擇對應layout，
不可把同一layout重複套給整組。每句消費原始control、operand、glyph rows、pages、
上下框與完整opening／mouth／closing生命週期；陣列長度、tuple或資產不一致即
失敗即關閉。證據等級為`RE-CLOSED／DATA-READY`，尚非原版同狀態E2。

已完成的 E1 垂直切片：

- handler IR 保留 `0x242C9→0x24336`、證據等級與本檔，編譯器只對 exact
  no-argument caller 降成具型別 `native_ch20_sky_key_sequence`。
- 可編輯 campaign 依序保留 layout、對話、ACT63／64、配方、101幀 FDOTHER
  合成、ANI #0、白閃／還原、JOIN 24／23、sync party、chapter21 與
  `town_ch22`。正式接線與回歸狀態以 2026-08-27 的後續勘誤為準。
- 執行器在變更相機前預檢全部 FDOTHER RLE、ANI 索引幀與 DAC；資產、indexed
  map、payload 或視圖不完整時失敗即關閉。
- 決定性回歸從正式 `battle_ch21` 勝利確認進入配方成功分支，逐相位呈現後停在
  `town_ch22`，並驗證天空之鑰、JOIN chronology、persistent roster 與城鎮存讀檔。

尚未宣稱：

- 未修改 DOS 一般玩家路徑與重製相同戰場狀態的逐幀／音訊 E2 比較。
- `0x4DFCC` 在實際 caller 第一次呼叫時的程序全域 phase 與 BIOS tick latch 精確值。
- DOS BIOS tick 與60Hz主機時鐘逐毫秒一致；重製只保留原始順序及約略等待。
- layout／ACT63／64 的 typed 消費端可由本節提升至 E1，但未修改原版同狀態
