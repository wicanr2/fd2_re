# `sub_1F894` 開場捲動／AFM 交錯排程（IDA 主證據）

## 輸入與工具

- 輸入：`FD2.EXE`，357074 位元組
- MD5：`b97caf2239a27a896069d03549d96e1e`
- SHA-256：`222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- 主工具：IDA Pro 9.4／Hex-Rays `9.4.0.260610`，LE 線性位址空間，
  `fd2-ida-authorized-local:latest`，2026-08-26，一次性 Docker、原版唯讀。
- 第二工具：Capstone 5.0.3，LE 線性位址空間，`fd2-cap-local:latest`。
- 原始 IDA 名稱全部保留：`sub_1F894`、`sub_1F73F`、`sub_1F81E`、
  `sub_20421`；本檔語意名稱只是附加導覽，不取代原始定位。

## 問題與裁決

問題：重製端舊 `cutScript` 把 AFM／靜態幕全部播完後才單獨捲動，是否符合原版？

裁決（**已證實**）：不符合。`sub_1F894` 的主迴圈以 `esi=0x217`（535）開始，
每輪先把 `scroll_buffer + esi*320` 的320×200視窗複製到 VGA，再依目前 `esi`
同步插播 AFM 或靜態幕；插播返回後仍在同一迴圈，等待30ms、遞減 `esi`，下一輪
重新複製下一個完整捲動畫面。AFM／靜態幕是暫停點，不是捲動前後的獨立串列。

## `sub_1F894` 前導發行商畫面（已證實）

主捲動前另有一段不能省略成 AFM 3 的前導畫面。IDA 9.4 直接指令固定如下：

```text
0x1F8D6  push 4Dh                         ; FDOTHER #77
0x1F8DE  call sub_111BA                   ; 2026-08-29 raw bytes 勘誤
0x1F8FD  push 4Ch                         ; FDOTHER #76，768-byte VGA palette
0x1F902  call sub_111BA
0x1F927  push 4Ah                         ; FDOTHER #74，320x200 0x4E63D frame
0x1F92C  call sub_111BA
0x1F93B..0x1F94A  call sub_4E63D           ; blit #74 to VGA
0x1F952  call sub_1F525                   ; palette fade-in
0x1F957  push 1;   call sub_17AA9
0x1F961  push 1Eh; call sub_17AA9          ; total 31 BIOS ticks
0x1F96B  call sub_1F882                   ; palette fade-out
```

玩家自備固定版 `FDOTHER.DAT` 的三個 raw entry：

| entry | bytes | MD5 | SHA-256 | 裁決 |
|---:|---:|---|---|---|
| 74 | 6585 | `48533366ad6a23bd6af906d88cbd39c6` | `fa2e695f2a25430802d03154ff6bfdd3372aa3e89c912a67dc6da70cb5cd42e5` | `40 01 c8 00` 幾何；以已證實 `0x4E63D` 四模式 RLE 解出320×200畫面 |
| 76 | 768 | `2eff61ca4274827d5a24ac89632da7b0` | `79d17da02ec2e5b0b14d2ebc9dd156d9ab69d7fc99df5008847dfa33fe72139d` | 256×RGB 六位元 DAC palette |
| 77 | 52031 | `3c0a8e570be878a9eea436c7d79375aa` | `4276bfc6bf4b9f7ae0815f4f15a8f74aff33c5c29d4a2b5d2a5a6ec30540ce13` | `LLLLLL` 巢狀資源；本切片不替它猜測高階名稱 |

`remake/cmd/fd2-title-prelude-oracle` 只從玩家自備 `FDOTHER.DAT` 重生證據圖；
`#74 + #76` 的可見內容是黑底「漢堂國際資訊」發行商標誌。現存本機
`extracted/title_re/dosbox_seq/frame_000.png` 已是後續 AFM 3 的龍紋過渡幀，
不是發行商標誌；舊文件以它作為「從漢堂標誌起算」的時間原點已撤回。

`sub_17AA9` 的 `[0x46C]` 是 BIOS tick source；重製依公開 18.2065Hz 契約把31 tick
投影為約1.70秒。`sub_1F525`／`sub_1F882` 各自已由其他 canonical 證據閉合為
65×2ms淡入／64×2ms淡出。這是硬體規格近似，不追 DOS busy-wait 的逐週期一致。

## 直接指令與資料流

### 主迴圈、畫面來源與30ms步進（已證實）

```text
0x1FA85  mov esi,217h
0x1FA8C  dec esi
0x1FA8D  test esi,esi
0x1FA8F  jl 0x1FC66
0x1FA95..0x1FABB  push 0C8h,140h,140h,(edi+esi*320),140h,0A0000h
0x1FABB  call sub_11EB0
0x1FC3A  push 1Eh
0x1FC40  call j___delay
0x1FC48  test esi,esi
0x1FC4C  push 3E8h
0x1FC51  call j___delay       ; 只在 esi==0 額外停留1000ms
0x1FC59  call sub_10620       ; 每一列後檢查 pending key
0x1FC60  jz 0x1FA8C
```

`edi` 是 `0x1FA1E..0x1FA55` 將 FDOTHER `#0x45..#0x49` 五張320×147圖
依 `147*index` 疊成的320×735緩衝。`sub_11EB0` 的來源寫入端與下一輪 consumer
共同證實：任一插播結束後，主迴圈會重繪當前捲動視窗再繼續。
`sub_10620` 回傳非零時不跳回 `0x1FA8C`，而是直接進 `0x1FC66` wipe／標題揭示；
所以捲動區間的任意鍵會略過剩餘捲動與尚未觸發的中間幕。這與 AFM 第三參數是兩個
不同 owner：不可中斷的 AFM 本身仍不輪詢按鍵。

### 明確 `esi` 觸發點（已證實）

```text
0x1FADD  cmp esi,19h       ; 25  → sub_1F81E(index0,delay15,palette0)
0x1FB36  cmp esi,14Ah      ; 330 → index4,delay90,palette99；接 index5,delay50,palette0
0x1FB59  cmp esi,0D2h      ; 210 → index6,delay90,palette99；接 index7,delay50,palette0
0x1FB7F  cmp esi,6Eh       ; 110 → index8,delay90,palette99
0x1FB94  cmp esi,1C2h      ; 450 → sub_1F73F(scroll, palette99, image100)
0x1FBA4  cmp esi,0Ah       ; 10  → sub_1F73F(scroll, palette76, image75)
```

呼叫參數由 caller 的右到左 push 直接固定：

```text
0x1FB43..0x1FB49  push 63h; push 5Ah; push 4; call sub_1F81E
0x1FB51..0x1FAE8  push 0;   push 32h; push 5; call sub_1F81E
0x1FB66..0x1FB6C  push 63h; push 5Ah; push 6; call sub_1F81E
0x1FB74..0x1FAE8  push 0;   push 32h; push 7; call sub_1F81E
0x1FB89..0x1FAE8  push 63h; push 5Ah; push 8; call sub_1F81E
0x1FAE2..0x1FAE8  push 0;   push 0Fh; push 0; call sub_1F81E
```

`sub_1F81E` 於 `0x1F870..0x1F87A` 把 `(index,delay,0)` 轉交
`sub_20421`，所以迴圈內六個 AFM 都不可按鍵中斷。迴圈前
`0x1F9AC..0x1F9B2` 直接呼叫 `sub_20421(3,90,1)`；轉場後
`0x1FD0E..0x1FD14` 直接呼叫 `sub_20421(1,15,1)`，只有這兩幕可中斷。

### 靜態幕返回捲動來源（已證實）

`sub_1F73F` 唯一 caller 是 `0x1FBAF`。它在完成圖像載入、淡入、停留與淡出後：

```text
0x1F7C9..0x1F7D6  load FDOTHER #65 palette
0x1F7E3..0x1F80F  sub_11EB0(dst=0xA0000,src=scroll_base+esi*320,320x200)
0x1F817             call sub_1F525
0x1F81D             retn
```

這直接證實靜態插播會恢復 caller 傳入的同一捲動視窗；重製端不得在靜態幕後跳到
另一份獨立背景或把捲動重設。

## 轉場尾段

2026-08-27 以同一 IDA Pro 9.4 `.i64` 補查 `sub_286BD` 的直接指令後，撤回本段
舊「wipe」名稱：它不搬移、遮罩或改寫 framebuffer，只對 VGA DAC 做線性調色盤
插值。caller 的 `end=255` 是半開區間，所以更新 index `0..254`、保留 index255；
不得誤寫成全部256色。原始函式名、位址與運算元保留如下。

### `sub_286BD` 插值公式（已證實）

`sub_286BD(start,end,phase,baseR,baseG,baseB)` 對半開區間 `[start,end)` 的每一色：

```text
0x286CB  mov edi,[arg_8]                  ; phase
0x286D3  mov ebp,28h                     ; denominator 40
0x286DD  push ebx; push 3C8h; call outp  ; DAC index
0x286F2..0x28710  out = baseR + phase*(palette.R-baseR)/40
0x2871E..0x2873B  out = baseG + phase*(palette.G-baseG)/40
0x28749..0x28766  out = baseB + phase*(palette.B-baseB)/40
0x28774  inc ebx
0x28775  cmp ebx,[arg_4]; jl 0x286DD
```

除法是 signed `idiv 40`，故中間負差值依 x86 規則向零截斷；重製的逐相位精確
indexed adapter若日後需要 E2，必須保留此捨入，不可改成無條件 floor。

### 第一段：目前畫面轉純紅（已證實）

```text
0x1FC66  mov esi,28h
0x1FC6D..0x1FC7B  sub_286BD(0,255,esi,63,0,0)
0x1FC83  delay(8)
0x1FC8D  dec esi
0x1FC90  jge 0x1FC6D
0x1FC92  delay(100)
```

phase由40遞減至0，共41相位：第一幀是目前 palette，最後一幀的 index `0..254`
皆為六位元純紅 `(63,0,0)`，index255維持原值。它只改 DAC，最後的惡魔臉
indexed framebuffer 保持不變；現有原版frame186仍因可見像素不使用不同的index255
而呈現整幀純紅。

### ANI #1 與第二段：近白標題轉原色（已證實）

```text
0x1FCB6..0x1FCE4  load FDOTHER #7 and palette #8
0x1FCE9..0x1FCFA  clear VGA
0x1FD0E..0x1FD14  sub_20421(1,15,1)       ; ANI #1，真實 logo 揭示
0x1FD2C..0x1FD35  sub_11DF2(0,255,64)     ; saturate DAC
0x1FD3D..0x1FD4A  sub_16886(VGA,320,#7,0); draw final title base
0x1FD52  xor esi,esi
0x1FD56..0x1FD64  sub_286BD(0,255,esi,56,60,63)
0x1FD6C  delay(8)
0x1FD76  inc esi
0x1FD7A  jle 0x1FD56
```

第二段 phase由0遞增至40，共41相位：index `0..254`從近白六位元基色
`(56,60,63)` 回到 palette #8 原色，index255仍保留。DOSBox `frame_185..194`
的純紅→黑／ANI #1縮入→泛白→穩定選單
順序與此資料流一致；影片只作動態旁證，直接指令才是主證據。

## 重製映射與證據邊界

- 可安全實作：535→0 的捲動位置、30ms步進、上述六個明確觸發位置、AFM index／
  每幀 delay／skippable、捲動列後的任意鍵略過、兩個靜態幕與1000ms尾停；插播後
  回到同一捲動位置。
- 60Hz 重製以累積毫秒而非逐 DOS busy-wait 近似；這是玩家可見時序映射，不重現
  DOS `INT 21h` 或硬體 wall-clock。
- 兩段 palette 插值與 ANI #1 的 caller 排程已閉合；60Hz 重製可依328ms映射為
  每段20幀，這是玩家可見近似，不是41個 DOS DAC 相位逐一 present。沒有相同時間戳
  原版畫面前仍不能外推逐像素／逐音訊 E2。
- 原版影片從開場到屠龍閃光約14.7秒，整段至標題約32.3秒，僅作動態交叉驗證；
  位址、caller 與直接指令才是本排程主證據。

狀態：`RE-CLOSED`。只有輸入雜湊不同、上述直接指令被反證，或正式 runtime 的
同狀態畫面順序與原版矛盾時才可重開；不得再以舊 `cutScript` 或單一影片印象重解。
