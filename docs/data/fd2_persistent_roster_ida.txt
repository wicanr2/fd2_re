FD2 persistent roster 0x50-byte record（IDA Pro 9.4）
====================================================

證據等級：下列欄位均有原版 writer 與特定 consumer；未列出的 bytes 維持未知。

輸入版本
--------

- `FD2.EXE`，357074 bytes
- MD5 `b97caf2239a27a896069d03549d96e1e`
- SHA-256 `222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- 基準：`docs/data/fd2-reference-files.json`

工具與隔離
----------

- 第一順位：合法 IDA Pro 9.4，使用
  `/home/anr2/ida_94_official/dist` 所建的 `fd2-ida-authorized-local`。
- 原版與授權檔唯讀；一次性資料庫只寫入 `/tmp/fd2-ida-roster`。
- `--network=none`，完成後刪除暫存資料庫及容器。

記錄建構器 `0x112A5`
--------------------

`[0x53BFB]` 是 append index；`0x112B6..0x112CC` 以
`[0x53BF7]+index*0x50` 定位新 persistent record。直接 writer：

| offset | writer | 狹窄結論 |
|---|---|---|
| `+5` | `0x11337` | raw byte5 初值 0 |
| `+6` | `0x1133B` | raw camp／selector byte 初值 2 |
| `+7` | `0x1133F..0x11343` | caller join id 寫入的可變 presentation/resource key |
| `+8` | `0x11343..0x11346` | 同一 join id；另由 `0x33499` 作 persistent identity lookup |
| `+0A..+15`、`+16/+18` | `0x1134D..0x11399` | 前六格 flags／item 與最後兩格 flags；最後兩格 item `+17/+19` 未在此寫入，見下方勘誤 |
| `+1A..+1D` | `0x11399..0x113A3` | constructor command bytes |
| `+1E` | `0x113AB` | 第五個 command byte 初值 0 |
| `+1F/+20` | `0x113AF..0x113B7` | race／class raw bytes |
| `+21` | `0x113BA..0x113BE` | level byte |
| `+22..+27` | `0x113C1..0x113C9` | 六個 transient bytes 初值 0 |
| `+37/+39` | `0x113D5..0x11400` | constructor base AP／DP signed words |
| `+3B` | `0x11404..0x11407` | movement byte |
| `+3C` | `0x1140A` | experience byte初值 0 |
| `+3E` | `0x1140E..0x11422` | DX signed word |
| `+40/+42` | `0x11426..0x1142E` | current／maximum HP words |
| `+44/+46` | `0x11432..0x1143A` | current／maximum MP words |

裝備衍生值 `0x1145A`
--------------------

`0x1145A` 讀 persistent record 的 base `+37/+39/+3E`，掃八個 item cells；
只有 raw flag `&0x40` 的 cell 會以 item id 查效果表。它最後寫：

- `+48`：base `+37` 加裝備 record `+1`
- `+4A`：base `+39` 加裝備 record `+5`
- `+4C`：base `+3E` 加裝備 record `+3`
- `+4E`：base `+3E` 加裝備 record `+7`

這些是原版衍生 AP／DP／HIT／EV writer；不可把 `+48..+4E` 再稱為螢幕座標。

狀態面板 consumer `0x17EEF→0x17FC0`
-----------------------------------

- `0x17F12..0x17F28` 以 runtime record `+7` 載入 DATO resource。
- `0x17FEB..0x18035` 顯示 `+40/+42` HP 與 `+44/+46` MP。
- `0x180A2..0x180ED` 顯示 `+21` level、`+3C` EXP、`+3B` movement。
- `0x18109..0x181AD` 顯示 `+48/+4A/+3E/+4C/+4E`。
- `0x181CE..0x1823C` 以 `+8/+1F/+20` 顯示名稱、race、class 文字。
- `+22/+23/+24` 在此只控制數值顏色；玩法狀態名稱仍由各 writer／caller
  決定，不能只靠畫面命名。

重製對應與限制
--------------

- `fdsave.PersistentRecord.View` 現以唯讀方式投影上述 offsets，所有 signed
  words 依原版 `movsx word` 保存。
- `RawPresentationKey` 與 `RawIdentity` 分開；不得推成 portrait、FDICON
  cache slot 或永遠相等的 character id。
- 此 view 尚不補角色名稱、class 名稱、圖像 resolver 或 chapter
  materialization，因此仍不是完整 `battle.Unit`／native restore。


2026-10-01 勘誤：JOIN 與戰後複製不能合併
------------------------------------------------
沿用同一 FD2.EXE identity、IDA Pro 9.4 線性位址及第七章已閉合證據。
原表把 +0A..+19 全列為 constructor writer 範圍過廣：0x11395 只寫
+0x16/+0x18 的旗標 80，+0x17/+0x19 保留載入記憶體的原值。
已證實的完整殘值範圍與實際存檔比較見 56 第七章章工作單元；
章節槽 LOAD 的全 0xA00-byte reader 是 0x2604A..0x26056，見
docs/data/fd2_native_chapter_slot_restore_ida.txt。0x10010 是另一條續戰入口。
較早 zero-initial materializer 的說明只適用零基底，不是所有 JOIN 的 ABI。

ch01-cleared 槽0 count5 的第5筆 item bytes 是 3f/06；ch02-cleared
identity8 同位置是 ff/ff。ch01_post 的 0x230D9 呼叫 sub_112A5 之後，
0x230E1 還呼叫 sub_11506。第七章證據已證實後者可整筆抄回 Own
場上記錄；因此最終 ff/ff 不能反推 constructor 寫 ff。
具體第一章當下場上 writer／copy-back 對照尚待 #23 的有界驗證。
本輪修正建槽工具的 constructor consumer，沒有宣稱整個戰後存檔已一致。
