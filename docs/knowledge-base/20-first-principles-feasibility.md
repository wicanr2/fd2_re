# 20 — 第一性原理:重製可行性再確認（能力盤點，不是完成宣稱）

> 設計完成後,用第一性原理把「能不能做出可玩的 FD2 重製」拆到不可再分的事實逐一確認。
> 結論先講:**資產保存與主要資料來源已足以證明「可做」，但 runtime integration、native UI/effect、campaign parity
> 尚未完成；本篇的「有」表示已有來源或垂直切片，不表示全 30 章等價可玩。反組譯覆蓋現況以 `58`，系統設計以 `56`，畫面證據以 `57`，待辦以 `91` 為準；`42` 只保留歷史盤點。**

| 2 | **畫角色/單位/動畫** | sprite + 戰鬥動畫 + 頭像 | ✅ FIGANI 2118 幀、DATO 136 頭像、FDSHAP sprite | `06`/`01`§7 |
| 3 | **顯示文字/劇情** | 字型 + 文本 + 對話框機制 | ✅ glyph→UTF-8 全表、控制碼、頭像對話框 | `08`/`09`/`14` |

## 為什麼這代表「可行」(第一性論證)

1. **資料可達性**：多數archive codec與主要圖／動畫／文字／地圖／音樂表已可
   抽取或解碼，足以證明工程可行；但runtime resource selection、indexed
   compositor、handler dataflow、音訊／DOS timing仍有未閉合黑箱。不能把
   「檔案可讀」寫成「所有資料與規則已完整還原」。
2. **可驗證性**:每個格式都用「強約束 + 視覺/聽覺/數值對照」驗證過(解碼必為 W×H、地圖渲染正確、
   數值對攻略字面值、MT-32 實際 render)。→ 不是紙上推論,是已重現的事實。
3. **引擎存在性證明**:同型別的跨平台 SRPG/策略遊戲已用 Go/Ebiten 做成(魔法大帝重製,桌面/Web/Android)。
   → 引擎能力不是未知數。
4. **降維**:把「線性 33 關」抽象成「節點圖 + 資料驅動」(`19`),使「擴充/分支」也落在已知工程範圍。

→ 結論:**資料與工具已證明工程可行；剩下仍包含 native dataflow／renderer 的研究與 campaign 整合，
不能用「只剩組裝」或「全遊戲完成」描述目前狀態。**

## 殘留風險與處置(誠實揭露)

| 風險 | 嚴重度 | 處置 |
|---|---|---|
| **戰鬥公式細節**(命中/暴擊/傷害的確切捨入) | 低 | 有攻略公式 + EXE 表;以 headless 回歸對齊,逐步校準 |
| **動畫播放時序**(每幀停留、迴圈點) | 低 | 有全部幀;時序用合理預設,再對照原版微調 |
| **少數控制碼**(0xFFFA/FB/FC 顏色等) | 很低 | 主要碼已解;罕見碼遇到再補 |
| **FD2.SAV 存檔相容** | 不影響 | envelope 已解為 rolling-XOR + checksum；重製仍刻意使用自有存檔格式(`19` 節點+旗標)，不把它宣稱為 native compatibility |
| **逐關平衡 / 觸發事件細節** | 低 | metadata 已有回合事件/寶箱;事件語意逐關對照補 |

→ 這些風險不否定工程可行性，但仍可能在正常玩家抽樣中形成必須修正的核心缺陷；
本表不能用來宣稱「沒有未知」或「沒有交付缺口」。

## 最小可玩垂直切片(MVP)的不可再分需求

要證明引擎可行,第一個垂直切片只需:**載入序章地圖 → 部署 4 名我方 → 對 AI 敵人走位/攻擊 → 達成勝利 → 播一段對話**。
這是早期用來證明技術可行的MVP定義；目前已有更長的正式垂直切片，但當時的
「零件存在」不證明其原版語意、介面或一般玩家E2沒有缺口。

## 結論

從第一性原理看,**重製的每一塊地基都已驗證存在**:資料解得開、規則查得到、引擎做得出、流程設計得了。
專案已證明可行並進入工程整合與代表性驗證階段；仍有已知證據限制與抽樣尚未
覆蓋的風險。現行下一步以`91`有效佇列與`REMAKE-STATUS.md`為準。
