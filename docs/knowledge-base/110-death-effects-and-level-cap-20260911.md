# 110 — 死亡效果與升級上限（2026-09-11）

本輪把兩個原版行為接進重製端：單位倒下時的死亡效果（型態 0～3），以及升級的
上限與經驗歸零。途中順帶修掉兩個重製端的推測：升級時把新增的 MaxHP 補進目前 HP、
敵方或友軍擊殺也發放物品金錢。

原版證據一律綁定固定版本 `FD2.EXE`：357074 位元組，
MD5 `b97caf2239a27a896069d03549d96e1e`，
SHA-256 `222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`。
反組譯以 capstone（`tools/disasm_le.py`，`fd2-cap-local`）取得，位址為 LE linear；
記憶體運算元以 fixup 目標為準（例如 `[0x3a79]` 是 `0x53A79`）。

## 1. 升級：`0x1E292`

```text
0x1E2C9  cmp [0x53EC8], 0 ; je 0x1317D     這次行動沒有經驗就返回
0x1E2D6  test byte [esi+5], 1 ; jne 0x1317D 死亡旗標在就返回
0x1E2E0  cmp edx(+7), 0x1E ; je 0x1E2EA
0x1E2E5  cmp edx, 0x1F ; jne 0x1E2EF
0x1E2EA  cmp eax(等級), 0x63 ; jmp 0x1E2F2    機兵：上限 99
0x1E2EF  cmp eax, 0x28                        其餘：上限 40
0x1E2F2  je 0x1317D                           等級剛好等於上限就返回
...
0x1E3EE  sub [esp+4], 0x64                    每升一級扣 100
0x1E3F3  +7 為 0x1E／0x1F 且等級 == 99 → 經驗歸零（0x1E40C）
0x1E4F6  cmp eax, 0x1E ; jne 0x1E414          任何人升到 30 級 → 經驗歸零
```

`0x1317D` 是共用收尾（`add esp,0xc; pop ebp/edi/esi/ebx; ret`），和 `0x1E292` 的序言
一一對應，所以「返回」連經驗都不加，也不顯示「得到經驗值」。

獨立來源：`references/text/modify1.md` 的修改指南第 11～13 條改的正是這幾組位元組
（`83 F8 28 0F 84`、`63 EB 03 83 F8`、`1E 0F 85`），分別稱為「非機兵等級上限 40」
「機兵等級上限 99」「修正 30 級升級經驗歸零錯誤（應為 40 級）」。所以機兵就是
`+7` 為 0x1E／0x1F 的單位，而 30 級歸零是原版的錯誤；忠實模式照原版。

成長擲骰 `0x1E529` 是 `lo + rand % (hi − lo)`，結果加到傳入的欄位：`+0x42`（MaxHP）、
`+0x46`（MaxMP）等。之後的 `0x1B750` 只重算 `+0x48..+0x4E` 衍生 AP／DP／HIT／EV
（尾段共用 `0x114FB`）。整條升級路徑都不碰目前 HP `+0x40` 與目前 MP `+0x44`。

另外 `0x11959` 在發經驗前把這次行動的經驗壓到 99（物理攻擊路徑已實作）。

### 重製端

- `gainExp`：原版 `+7` 的單位套上限（等級剛好等於上限時整段不收經驗），每升一級後
  30 級或機兵 99 級歸零；有原版 `+5` 時死亡旗標在就不收經驗。沒有 `+7` 的自訂單位
  不套上限。
- `State.AwardExp` 回傳實際收下的經驗，攻擊與法術的結果用它顯示；到上限時是 0，
  畫面不再附「得到經驗值」。
- 升級只加 MaxHP／MaxMP。舊的「升級當下補血」是推測，已移除（issue #19）。
- 測試：`TestNativeLevelCapFollows1E292`（含反對照：拿掉判斷後六項紅燈）、
  `TestCappedAttackReportsNoExperience`、成長列測試的「目前 HP 不變」。

## 2. 死亡效果：收集與分派

FDFIELD 名冊 b22..b24 由 `0x10FA8..0x10FB2` 抄進 runtime `+0x31..+0x33`：
`{型態 u8, 值 u16le}`。

**收集 `0x1B6B7`**：依索引由 0 往上，挑「`+5` bit0 未設、`+0x31 != 0xFF`、HP ≤ 0」
的記錄，把三個 byte 抄進緩衝。呼叫端只有四個行動結算點（`0x1548E`、`0x18D8C`、
`0x1CFF0`、`0x20C6F`），都在攻擊演出之後。

**分派 `0x1AA1D(擊殺者索引, 筆數, 緩衝)`**：

| 型態 | 行為 | 位址 |
|---|---|---|
| 0 | 物品，只給原版陣營 `+6 == 2` 的擊殺者；背包滿時詢問轉交（`0x1AA56`） | `0x1AC7B` |
| 1 | 金錢加到 `[0x53BF3]`，同樣只給 `+6 == 2` 的擊殺者 | `0x1AB95` |
| 2 | `delay(200)` 後呼叫全域事件表 `0x51B91[id](擊殺者索引)` | `0x1AC0A..0x1AC1A` |
| 3 | `0x15F84([0x53A79], 值, 0xA0000, …)`：顯示章節戰場文字庫的一句 | `0x1AC2B..0x1AC49` |

型態 3 與第一關回合事件在 `0x34242` 顯示對白的呼叫完全相同（同文字庫、同目的地、
同樣式參數）。`[0x53A79] = 0x111BA("FDTXT.DAT", 舊指標, [0x53C03]+1)`
（`0x101DC..0x101F6`），所以第 k 關的戰場文字庫是 FDTXT_0kk。第一關海盜首領的
`[3, 8]` 是 FDTXT_001 第 8 句「可恨啊！……真是天亡我也！」。

**經驗與勝負的順序**：`0x11943` 呼叫玩家行動（`0x18890`，攻擊與死亡分派都在裡面），
返回後 `0x11959` 才把經驗壓到 99、`0x1196D` 才呼叫 `0x1E292` 發經驗、`0x1197B` 呼叫
各章的行動後 hook。所以死亡處理器可以取消這次行動的經驗（事件 30），而勝負要等
死亡台詞播完才判。

## 3. 型態 2 的 23 個處理器

`tools/extract_native_death_events.py` 逐一轉寫，輸出
`remake/assets/data/native_death_events.json`。每個動作宣告它對應的原始指令範圍，
工具重新反組譯並用動作專屬的樣式核對參數；另從處理器入口沿著跳躍走到 `ret`，要求
每條非序言／收尾指令都被某個動作或條件認領。反對照：參數抄錯、漏一個動作、參數
順序顛倒三種變造都會失敗。

用到的原語：

| 原語 | 原版 | 語意 |
|---|---|---|
| `dialogue` | `0x15F84([0x53A79], N, 0xA0000, …)` | 章節戰場文字庫第 N 句 |
| `ai_mode_range` | `0x3419C(first, last, mode)` | `+0x34` 低四位 |
| `ai_byte_set_range` | `0x34A85..0x34AA5` 迴圈 | `+0x34` 整個覆寫 |
| `ai_byte_and_range` | `0x34A0E` | `+0x34 &= mask`（10..27） |
| `record_bytes` | `mov [eax+off], v` | 直接寫記錄欄位 |
| `control_turn` | `[0x53A55]+3+3×slot = [0x53BEF]+delta` | 回合事件排程 |
| `state_set`／`state_inc` | `[0x53AD5]+i` | 戰場區域狀態表 |
| `spawn_group` | `0x10B4E(group)`，`[0x53AFA]` 為 gate | 生成群組 |
| `staging` | `0x35822(x, y, group)` | pan、延遲、白閃、生成、重畫 |
| `pan`／`acting`／`reset_pose` | `0x135DD`／`0x1366A`／`0x134E4` | 鏡頭、演出、姿勢歸零 |
| `mark_inactive` | `0x32975(unit)` | `+5` 整個寫 1 |
| `clear_hp_from` | `0x35BBA(first)` → `0x1DB65` | 從 first 起 HP 清零，倒下呈現 |
| `range_one` | `[0x51A83] = 1` | 地圖範圍選擇值回到互動值 |
| `reward` | `0x1AA1D(擊殺者, 1, rodata)` | 硬編碼的三個 byte（`0x52742` 等） |
| `exp_cancel` | `[0x53EC8] = 0` | 這次行動沒有經驗 |

條件寫在各動作的 `when`：`state_eq`／`state_ne`（狀態表）、`round_lt`（事件 23：
第 15 回合前才放援軍）、`any_active`（事件 19：7..36 還有人在場才播第二句）。
條件在執行到該動作時才判斷，與原版讀取的時間點相同。

幾個有代表性的處理器：

- **事件 4**（第一關哈諾）：記錄 13（哈瓦特）的 `+6` 從 2 改成 1（交給 AI），播第 7 句
  四段「老爸，我不行啦……我和你們拼了！」。
- **事件 30**（第九關萊汀）：萊汀是記錄 11（第九關出場 11 人），倒下時被改寫成
  身分 6 的友軍、HP 1、死亡效果清成 0xFF；其他敵人 AI 歸零；排程後兩列回合事件；
  播兩句、生成群組 1；並取消這次擊殺的經驗。
- **事件 39／41／51**：給硬編碼物品 0xD3／0xD5／0x65，並播頭目台詞。舊的降階只給了
  物品、漏了台詞，現在改由程式唯一負責（`death_reward` 不再產生型態 2 的物品）。
- **事件 53／64／71／83**：頭目倒下時從某個索引起全員倒下（勝利）。

map31 的事件 4／5 在劇情地圖上，不打仗，不轉進劇本。

## 4. 劇本與執行期

`tools/sync_native_death_programs.py` 把轉寫降成各章劇本的
`native_death_programs`（鍵是「型態:值」），對白用 `count-aligned.json` 展開成逐段
原生參照，其餘原語放在 `native_death_op`。它同時：

- 把死亡事件生成的群組移出 `initial_groups`：第六關群組 2、第九關群組 1、第十二關
  群組 3／4。原版這些群組是頭目倒下才出現；開局就在場會讓記錄順序整個位移（第六關
  事件 23 的「記錄 33 離場」就會指到錯的人）。
- 移除第一關手寫的 `hawat_berserk`（從來沒有被觸發，由事件 4 取代）。
- 同步編輯器 canonical 文件。

執行期（`remake/cmd/fd2/native_death_program_runtime.go`）：

- 擊倒當下 `awardDeathReward` 處理型態 0／1（只給我方擊殺者），型態 2／3 排進佇列。
- 行動收尾 `finishSuccessfulUnitAction` 依記錄順序執行；型態 2 前面加 200ms。
  佇列在開始時換成記錄索引，因為 staging 與倒下呈現會替換單位快照。
- 勝負判定在死亡程式跑完前延後，跑完再判一次。
- 攻擊結算前先查被擊倒的單位有沒有無條件的 `exp_cancel`。
- 章節還沒有原生視圖與 HUD 狀態時，死亡台詞退回一般對白框（該章的回合事件也是如此），
  文字與說話者取自同一行故事腳本。
- 正在分派的倒下單位仍可當身分型說話者：原版在分派時 `+5` bit0 還沒設。
- 寫入還沒建構的記錄是無作用：原版照寫 raw 陣列，之後建構器整筆覆寫。

測試：battle 套件的原語、條件、復活、回合排程、投影同步、取消經驗與全部戰場的資料
覆蓋；介面層的第一關頭目台詞在勝利前播完（反對照：拿掉延後判定就會在台詞中判勝）、
事件 4 讓哈瓦特轉成友軍、缺程式時停下並指出鍵、只有我方擊殺者拿獎勵，以及逐章
實跑（`TestNativeDeathProgramsRunInEveryChapter`）：每章直接進戰場，找到或生成帶該
效果的單位，由我方擊倒，要求程式跑完且沒有執行期錯誤。它每個子測試載入一整套遊戲，
一般回歸跳過；要跑時設 `FD2_DEATH_SMOKE=1` 並分批（每批一個 `go test` 程序），例如
`-run 'TestNativeDeathProgramsRunInEveryChapter/(ch0[1-9])'`。2026-09-12 分批跑完 30 章：
劇本裡的 61 個死亡程式各成一個子測試，全部通過、沒有略過；第 27 關的 `2:64` 沒有程式，
不在其中。離屏測試不走 Draw，staging 閃白與 `0x1DB65` 倒下呈現要由測試的 `ackPresents`
承認已繪製，否則會停在等待繪製。
