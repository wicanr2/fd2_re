# 106 — 物理攻擊的結算鏈、反擊條件與傷害公式（2026-09-10）

原版一次物理攻擊會結算兩次：攻方先打，守方若符合條件就還手。本檔把那條鏈從
指令環一路解到傷害公式，並釘住反擊的三個條件。

## 輸入、工具與位址空間

- 輸入：`FD2.EXE`，357074 bytes，MD5 `b97caf2239a27a896069d03549d96e1e`，
  SHA-256 `222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- 第一順位工具：IDA Pro 9.4／Hex-Rays，授權 Docker
  `fd2-ida-authorized-local:latest`，入口 [`tools/ida.sh`](../../tools/ida.sh)
- 執行期裁決：dosgolem `apps/fd2/cmd/oracle`（`c8aa69a`），控制序列
  [`ch01-move-attack.jsonl`](../data/parity-plans/ch01-move-attack.jsonl)
- 位址為 DOS LE loader 線性位址。IDA 原始名稱一律保留，未以語意改名取代定位。

## 先修正一個走錯的方向

上一輪的收據把物理攻擊接到 `sub_2A6BD`（通用效果管線），並據此把待辦寫成
「拆 `sub_2A6BD` 內四處 `call 0x2A289` 各對應哪個分支」。那條路是錯的。

以 `-eip-watch` 監看整段攻擊（step 355,000,000..375,000,000）的實測：
`0x2A6BD`、`0x1C75E`、`0x1C81F`、`0x26152`、`0x1CFF0` 的進入次數**全部是 0**，
而 `0x28A6C` 進入一次。物理攻擊走的是 `sub_28A6C`，不是 `sub_2A6BD`；
`sub_2A6BD` 那條是 command ID `<9`／`24`／`>0x1B` 的效果指令（`sub_1CFF0` 的
分派）。兩次 `sub_2A289`（狀態欄重畫）分別跟著兩次結算走，本身不是分支。

## 呼叫鏈（已證實）

| 位址 | 原始名稱 | 角色 |
|---|---|---|
| `0x18D8C..0x190AC` | `sub_18D8C` | 戰鬥指令 caller，依 `[0x53C57]` 分派；`0x18FC6` 呼叫物理攻擊 |
| `0x28A6C..0x29117` | `sub_28A6C` | 物理攻擊整段：載素材、`sub_29164` 滑入、兩次結算、收尾 |
| `0x2939D..0x29C90` | `sub_2939D` | 一次攻擊的結算＋逐幀演出，回傳守方最終 HP |
| `0x29F72..0x2A289` | `sub_29F72` | 傷害公式；把命中／暴擊／狀態／連擊與傷害填進呼叫者的六格陣列 |
| `0x1F0DC..0x1F183` | `sub_1F0DC` | 反擊資格判定 |
| `0x1B83D..0x1B8A6` | `sub_1B83D` | 找出某單位第 0 類已裝備槽（武器） |

`sub_28A6C` 另外三個 caller 是 `0x1548E`（AI 評分那條也會問 `sub_1F0DC`）、
`0x2BCE5` 與 `0x353DA`；本輪只走玩家指令環那條。

## 反擊的三個條件（已證實）

`0x28E76` 起的原始控制流：

```c
sub_29164(a1, v20, ...);                       // 全螢幕戰鬥畫面滑入，整段只一次
if ( sub_2939D(a1, a2, ...) != 0               // (1) 守方打完還活著
  && sub_1F0DC(a1, a2) == 1                    // (2) 守方有反擊資格
  && dword_540FF == 0 )                        // (3) 不在抑制模式
    sub_2939D(a2, a1, ...);                    // 攻守對調，這就是反擊
```

`sub_2939D` 的回傳值是守方最終 HP（`v29`，即寫進 `unit+0x40` 的那個值），
所以「非 0」就是「守方還活著」——**守方被打死就不會反擊**。

`sub_1F0DC(攻方, 守方)` 回 1 才算有資格，三項全要成立：

1. 守方 `unit+38` ＝ 0（非零直接回 −1）
2. `|dx| + |dy| == 1`，也就是**兩格相鄰**；隔空攻擊不會被反擊
3. 守方有已裝備的第 0 類裝備（`sub_1B83D(守方, 0) != -1`），且該裝備 record
   的 `+11` ＝ 1。record 由 `sub_4E56C(sub_1B722(守方, 槽))` 取得

`sub_1B83D(unit, 0)` 掃 8 個槽（`unit + 10 + 2*i`）：`+10` 的 bit `0x40` 表示
已裝備，`+11 < 0x80` 是第 0 類。回傳槽號或 −1。

`dword_540FF` 非零時整段不造成傷害（六格陣列全歸零、不重畫狀態欄），並改走
`0x28F17` 那一次 `sub_2939D(a2, a1, …)`。它的 writer 與用途本輪未解。

## 傷害公式 `sub_29F72(攻方, 守方, out[6])`（已證實）

單位欄位以 uint16 索引寫出，乘 2 就是 byte 偏移：

| 取用 | 偏移 | 意義（推論等級） |
|---|---|---|
| `v30 = *((u16*)攻方 + 36)` | `+0x48` | 攻擊力（強推論） |
| `v32 = *((u16*)守方 + 37)` | `+0x4A` | 防禦力（強推論） |
| `v31 = *((u16*)守方 + 32)` | `+0x40` | HP（已證實：結算寫回同一處） |
| `v26 = *((u16*)攻方 + 38)` | `+0x4C` | 命中率（強推論） |
| `v24 = *((u16*)守方 + 39)` | `+0x4E` | 迴避率（強推論） |
| `v25 = 攻方[32] - 1` | `+0x20` | 職業 ID 減一，用來索引 `byte_5239B` |

步驟：

1. **地形修正**：`sub_1F183(unit) == 0` 時，以 `sub_12E38(x, y, …)` 取該格地形，
   攻方 `攻擊力 += 攻擊力 * dword_51A12[地形] / 100`、守方
   `防禦力 += 防禦力 * dword_51A2A[地形] / 100`。

   `sub_1F183` 是飛行判定：`unit+7 ≠ 28` 且（職業 ＝ 19 或 `unit+31` ∈ {4,5}）
   時回真，回真就**不套**地形修正。職業 19 是龍騎士。

   地形碼來自 `sub_12E38(x, y, buf)` 的 `buf[5]`：它以 `dword_53A51` 的
   `4*(x + 寬*y) + 4` 取 tile（高位元 `& 3`），再讀 `dword_53A69[4*tile + 1]`。
   那正是重製端 `NativeTerrainMoveCodes` 承載的 control byte。
2. **武器特效**：攻方武器 record 的 `+9` 決定分支，`+10` 是參數。
   `4` ＝ 暴擊率加上 `+10`；`2` ＝ 以 `+10`% 機率讓守方 `+37` 變成
   `rand()%4 + 2`（狀態異常，`out[2]=1`）；`3` ＝ `out[4]=1`。
3. **命中**：`rand()%100 < 命中率 − 迴避率` 才命中。命中時 `out[0] = 0`
   （**0 是命中**，初值 1 是未命中）。
4. **暴擊**：`rand()%100 < byte_5239B[職業−1] + 武器加成` 時守方防禦力減半，
   `out[1] = 1`。
5. **傷害**：`傷害 = 9 * (攻擊力 − 防禦力) / 10`，負值取 0；再加
   `rand() % (傷害/9)`，也就是最多再多約 11%。
6. **寫回**：`守方 HP -= 傷害`，負值取 0。`out[5]` ＝ 傷害，也是回傳值。

`sub_2939D` 收到這六格之後才決定演出：`out[0]` 決定打空的表現，`out[1]`／
`out[2]` 決定兩段 DAC 閃色（`outp(0x3C8/0x3C9)`），`out[4]` 非零時把外層迴圈
計數加一——那是**連擊**，同一次指令內再打一次。另外 `sub_2939D` 進迴圈前有
`rand()%100 < 3` 就把次數設成 2，也就是 3% 的固定二連擊。

HP 不是一次扣完：演出期間逐格寫
`守方HP = 起始HP − 總傷害 * 已播格數 / 有效格數`，每寫一次就
`sub_2A289` 重畫狀態欄。這解釋了為什麼逐格取樣會看到 HP 一路降下去。

## 重製端接線與對拍

正式路徑（玩家攻擊與原版 AI）走 `AttackNativePhysicalWithExperience`：照本檔的
順序擲骰、用原版 RNG（`fdother.NativeRNGStep`）、含武器暴擊加成、沒有傷害下限，
守方符合條件就反擊。`combat.go` 的近似公式留給正規化 AI 與其測試，那條沒有產品
消費者，檔頭已標明它不是原版行為。

對拍用第一關那組座標，輸入全部取自原版 checkpoint 的 80 位元組 record 與 map0 的
地形碼（收據
[`fd2-physical-attack-parity-20260910.json`](../data/ui-traces/fd2-physical-attack-parity-20260910.json)）：

| | 原版實測 | 重製端公式 |
|---|---|---|
| 主攻（騎士打盜賊） | 守方 28→8，傷害 20 | 未暴擊 20 或 21、暴擊 22 或 23 |
| 反擊（盜賊打騎士） | 攻方 48→31，傷害 17 | **恆為 17** |

反擊那一擊不依賴挑 RNG 種子：盜賊職業暴擊率是 0，而 `9*(25−6)/10 ＝ 17` 讓隨機
加成的跨距只剩 1，所以窮舉全部 65536 個狀態，命中的每一次都是 17。主攻則是
25597 個起始狀態能連續重現兩次結算，含兩次 `sub_2939D` 開頭的 3% 判定。

## 尚未涵蓋

- `dword_540FF` 的 writer 與語意。
- 武器 record `+9`／`+10`／`+11` 的完整列舉；本輪只解出用到的四個分支。
- 守方 `unit+38` 的語意（只知道非零就不反擊）。
- 反擊是否使用與主攻擊相同的 `sub_29F72`——原始碼上是同一支，但反擊那次的
  素材參數（`v23`／`v25`／`dword_5411B`）不同，演出差異未逐幀比對。
- `unit+38` 重製端沒有對應欄位，反擊判定一律當 0（不阻擋）。
- 經驗值仍走重製端既有規則：原版的經驗鏈（`sub_1B6B7` 蒐集陣亡單位 →
  `sub_1AA1D` 只對攻方跑一次）在 `sub_28A6C` 之外，本輪未解。反擊不給守方經驗
  這一點倒是可以從控制流讀出來——經驗處理只對 `a1`。
