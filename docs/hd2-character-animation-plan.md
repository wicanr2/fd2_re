# HD2／HD-2D 人物與動畫製作提案

狀態：製作路線已確認，2026-11-11。使用者選定「3D 骨架離線渲染，先做一人樣本」，首個樣本採本提案的索爾。工具鏈、正式資產格式與角色造型仍待樣本驗證，尚未接入遊戲。HD1 修正與推廣片重錄繼續優先進行。

採用「角色建模一次、骨架製作動作、離線渲染成透明圖格」。遊戲顯示預先製作的圖格，讓繪圖與動畫修訂不必依賴逐張生成。骨架負責結構與運動；面容、比例、服裝、蒙皮與材質仍須先做好。

## 已有基準

- 沿用[首章四人原型](data/fd2-hd2-first-slice-20261105.json)已選定的中央戰場畫風，以及站姿約 168 像素的尺寸基準。亞雷斯量帽頂至腳底，槍尖另計。
- 身份、面容、裝備與配色回查各自原版頭像、地圖人物及戰鬥影格。既有單張站姿只作參考，尚無可重用的角色模型或骨架。
- HD2 與 HD-2D 是既有主題規劃中的兩個方向。共用製作方法不等於合併主題，也不等於批准新的戰鬥造型或 3D 場景架構。

## 製作流程

| 階段 | 做法 | 審查與產出 |
|---|---|---|
| 角色設定 | 固定正面、側面、背面、頭身比、武器與服裝；未知遮蔽部分明列 | 身份參照表與轉面圖，先確認再製模 |
| 建模與材質 | 建立一次可轉向的網格，採手繪材質與柔和陰影 | 轉台圖與 168 像素實際尺寸比較；避免塑膠質感 |
| 綁骨與蒙皮 | 固定骨長、關節限制、手握武器與落腳控制；檢查彎曲處權重 | 同一模型完成抬手、蹲身、轉腰等壓力姿勢 |
| 動作庫 | 製作關鍵姿勢、預備、出招、停頓、收勢；相容體型間重定向 | 每個動作有完整片段，逐人檢查穿模、滑步與武器握點 |
| 離線渲染 | 固定正交鏡頭、畫幅、燈光、色彩設定、地面原點與透明背景 | 批次輸出 RGBA 圖格；相機角度先與已選概念圖比對 |
| 圖集編製 | 固定落腳點、保存裁切偏移、保留武器與特效外擴，分開身體與光效 | 來源版本、雜湊、尺寸、方向、時間及事件對照；格式另走 READY 規格 |
| 遊戲載入 | 延用現有 2D 顯示能力，分批載入需要的動作與畫質 | 原版／HD1 切換、遮擋、缺件拒收、記憶體及實機效能驗證 |

建議工具為 Blender 的骨架、蒙皮、動作與批次渲染能力。現有主機沒有已登錄的 Blender 專用映像檔；正式試作前，先鎖定實測版本、下載雜湊與 Docker 建置來源，不先宣稱工具鏈可用。製作工具的 GPU 加速與玩家電腦的 GPU 支援分別驗證。

## 骨架不能全部共用

| 類型 | 共用範圍 | 必須另處理 |
|---|---|---|
| 人形 | 待機、步態與基礎受擊的動作結構 | 身高、臂長、持武器手、長髮與衣擺 |
| 蓋亞 | 動作節點與時間標記 | 機械關節、裝甲硬件、原版頭身輪廓，不套人類蒙皮 |
| 龍人 | 可參考人形動作的節奏 | 龍頭、尾巴、足型與特殊比例，不直接放大人形骨架 |
| 騎乘角色 | 騎乘者上身動作可部分重用 | 馬的步態、騎手與馬的同步、韁繩及武器 |
| 特殊生物 | 相同構造才考慮共用 | 獨立骨架與動作，先確認原版造型 |

角色比例由已確認的造型決定。HD1 的龍人 115% 不自動變成 HD2 的比例規則。

## 動畫內容與時間

| 用途 | 第一批片段 | 製作重點 |
|---|---|---|
| 地圖 | 待機、走行、轉向、施法、受擊、倒地 | 先覆蓋目前遊戲會用到的方向；八方向只作能力試驗 |
| 普通戰鬥 | 預備、揮擊、命中停頓、收勢、受擊、防禦、倒地 | 出招要有重量感，武器輪廓完整；大圖比例與鏡頭另做視覺確認 |
| 魔法與絕招 | 角色動作、武器軌跡、火焰／光效、鏡頭提示 | 分層製作，以同一時間軸對齊；各招保留自己的分鏡 |

原版規則決定何時扣血、播放聲音與完成動作。新增的中間姿勢只改善呈現，不能重觸發傷害，也不能靠加速背景音樂配合畫面。音速刃、熾炎刀及淒煌斬等已還原招式沿現有證據，不重新猜規則。

遊戲更新率、螢幕幀率與素材張數分開規劃。先以 24 張／秒作製作試驗，再比較快速武器動作的 30／60 張取樣；不預設每個角色每個動作都保存 60 張。若 256×256 RGBA 圖格每段 24 張、8 方向，全量未壓縮像素約 48 MiB；每段 60 張約 120 MiB，尚未計 mipmap、暫存與多角色。實際尺寸、圖集配置及載入策略須量測，PNG 壓縮後檔案大小不能代表 GPU 記憶體。

先量測當前方向與所需動作的常駐量，再訂快取預算；避免整份角色動作庫一次載入。以多角色同屏、首用動作與反覆切換抽樣停頓，不能只看單一角色的空場示範。完整／均衡／輕量派生也須比較實際尺寸可讀性與顯示成本。

腳步採原地動作配合既有格子移動，腳部接觸與位移速度共同校準。動畫循環接縫、衣擺與粒子固定種子。相同版本和同一工具鏈重跑應可比對輸出雜湊；跨 GPU 或不同渲染版本不先保證逐像素一致。

## LLM 的位置

LLM 可協助整理原版參考、寫批次工具、動作清單及檢查報告。概念圖工具可輔助前期設計，須先確認身份與造型。正式逐拍圖片由同一個模型與動作渲染，不再每拍重新請 LLM 猜服裝、臉型與構圖。

渲染不足的局部需要修稿時，優先回改模型、材質或動作後整批重生。若逐張補畫，必須保存修補來源並重查時間連續性，避免重新引入漂移。

## 先做一條完整樣本

1. HD1 修正與新推廣片先完成。本次 HD2 只交規劃與隔離原型。
2. 首個正式美術樣本採索爾，因已有本人頭像與 168 像素站姿參考。先做轉面、待機與走行，再做普通揮擊；不一次展開全角色。施法流程後續用悠妮驗證。
3. 同屏比較已選站姿、骨架渲染與實際尺寸，確認手繪質感、面容、比例、落腳與動作後，才建立正式載入規格。
4. 接著用亞雷斯的長武器檢驗外擴與裁切，用蓋亞檢驗機械關節，確認方法能處理不同構造。
5. 完成一人從來源到遊戲載入的垂直樣本，再擴充動作庫與角色。正式大圖戰鬥、場景景深與燈光另有各自確認點。

每次交付至少保留角色轉台圖、實際尺寸動畫、透明圖格、模型／動作／工具版本、輸出雜湊，以及穿模、裁切、落腳、方向、事件時點與記憶體的檢查結果。尚未量測前不給全角色工期或效能保證。

## 這次可操作原型

[開啟骨架示意](../tools/fd2_hd2_rig_prototype.html)，可切四種動作、八個方向、12／24／60 張取樣、暫停與逐拍預覽，並下載當拍透明圖格。三欄共用同一套空間關節，分別顯示骨架、幾何替身與小尺寸結果。

這是 Canvas 的程式化空間投影，沒有使用 Blender 網格、正式蒙皮或遊戲素材。替身沒有身份，動作秒數、八方向、34 度相機仰角均屬試驗值，不能當成正式角色美術或原版時序證據。它只先展示固定結構如何重複產生多方向、多拍動畫。

[驗證器](../tools/verify_fd2_hd2_rig_prototype.mjs)在既有 `mcr.microsoft.com/playwright:v1.56.1-noble` 容器執行：`node tools/verify_fd2_hd2_rig_prototype.mjs tools/fd2_hd2_rig_prototype.html work/hd2-rig-plan-20261111-r96/browser-new`。輸出目錄須不存在；以非 root、無外網容器掛載專案執行。檢查骨長、160 組姿勢／方向、固定落腳索引、重播像素與三種視窗寬度；這些不等於正式角色動畫驗收。

使用者已選定「3D 建模綁骨後離線渲染」，先做索爾樣本。2D 分層切片不作本次主路線。下一個視覺確認點為索爾的轉面、實際尺寸與短動畫，不能用本頁無身份替身代替。尚未建模或改正式主題。
