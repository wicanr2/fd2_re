# v.1.1.16-20261126 發行說明

本版修正第 4 章撤退的獸人擋住勝利的問題，並一併收錄 v.1.1.15 之後已提交的兩次 Go 例外：HD 主題包按需解碼，以及關卡事件工具列與祕密商店直選。三平台完整版以新引擎重新打包，原版與 HD 素材與 `v.1.1.15-20261116` 相同。

Go 版自 `v.1.1.11` 起凍結，改寫主線是 Rust 版。本版對應使用者 2026-11-26 同意的例外，修正同步進 Rust 版，之後照舊凍結。

## 修正

| 項目 | 內容 |
|---|---|
| 第 4 章撤退獸人 | 第 2 群組的獸人有一隻倒下後，其餘會走回地圖邊緣離場。舊版獸人抵達後從畫面消失，卻仍被算成在場的敵人，打光其他敵人也無法結束戰役。現在獸人離場即不再計入，最後一隻離場時，若其他敵人也已不在場，就在同一個敵方回合判定勝利。 |

- 原版行為以 dosgolem 重現確認：撤退的獸人走了兩個敵方回合才回到邊緣，最後一隻抵達的當下原版就進入戰後對白。重現屬修改路徑，收據見 [`ch04-orc-retreat-r4.json`](../data/ui-traces/ch04-orc-retreat-r4.json)，規格見 [56「第四章撤退離場與勝負判定」](../knowledge-base/56-fd2-remake-sdd.md#第四章撤退離場與勝負判定)。
- 這條規則套用在所有讓敵人撤退離場的章節，不只第 4 章。

## 建置與驗證範圍

三平台引擎由來源提交 `3ae065cb`（修正本身是 `38a01d9d`）在本機 Docker 建置，方式同 v.1.1.11，見[打包文件 §4.4](../knowledge-base/41-packaging.md#44-本機-osxcross-建置使用者2026-11-13定案)。

| 平台 | 已驗證 |
|---|---|
| Linux | 引擎包與完整包在 Xvfb 下自檢；完整包開場受控截圖 |
| Windows | 引擎包與完整包在 Wine 10 下自檢；完整包開場受控截圖 |
| macOS 通用版 | 只做靜態檢查：雙架構、arm64 簽章、只連結系統框架、最低 macOS 11.0 |

三包各 54581 份素材已獨立解包逐檔核對，與 v.1.1.15 相同。Linux 與 Wine 的開場截圖相同，也與 v.1.1.15 相同（SHA-256 前綴 `affb593a`）。

修正本身的驗證：
- Go `TestAIStepMode7DepartureEndsBattleWhenNoEnemyRemains`：撤退者抵達後離場、HP 不變，同一敵方回合判勝。同一測試放回修正前的提交會失敗，失敗狀態與玩家回報一致。
- Go 與 Rust 各新增 `MarkNativeUnitInactive` 單元測試；Go 黃金工具對 Rust 的規則差分 99 場、36552 步一致。
- Rust fd2-rules（fmt、clippy、656 項）與 fd2-game（458 項）通過。
- `cmd/fd2` 全套測試在本機素材根有 19 項失敗、字串盤點 1 項失敗；以同樣輸入跑修正前的提交，失敗名單相同，皆為既有問題。

macOS 版在 Linux 上無法執行，沒有任何執行證據；Windows 的自檢在 Wine 執行，不等於原生 Windows。Windows、macOS 未簽署，macOS 未公證，首次開啟需右鍵選「打開」。
