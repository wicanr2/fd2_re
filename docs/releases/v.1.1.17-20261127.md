# v.1.1.17-20261127 發行說明

本版修正部分反擊會讓遊戲停在錯誤畫面的問題（#321），並收錄 v.1.1.16 之後已提交、Go 版也會讀到的一筆第 22 章戰後版面資料勘誤。三平台完整版以新引擎重新打包；素材除了這筆勘誤的 `assets/cutscenes/bindings/ch22_post.json`，其餘與 `v.1.1.16-20261126` 逐檔相同。

Go 版自 `v.1.1.11` 起凍結，改寫主線是 Rust 版。本版對應使用者 2026-11-27 同意的例外，修正同步進 Rust 版，之後照舊凍結。

## 修正

| 項目 | 內容 |
|---|---|
| 反擊停在錯誤畫面（[#321](https://github.com/wicanr2/fd2_re/issues/321)） | 主攻方的戰鬥動畫不帶背景旗標、反擊方帶旗標時，舊版找不到反擊要用的三層背景，停在「physical attack scene unavailable」錯誤畫面。第 18、22、25 章的對拍重播都碰到這種組合。現在照常載入 `BG.DAT` 三層，反擊畫面與一般反擊相同。 |
| 第 22 章戰後版面 | 戰後演出中第 16 號人物的朝向依原版資料改正（`ch22_post.json` 的 pose 由 0 改 2）。 |

- 原版在這種反擊會讀到已釋放或從未載入的背景指標，dosgolem 重現時在第 18、22、25 章都越界中止。重製端不重現中止，畫成一般反擊，這是使用者 2026-11-27 的定案。機制與證據見 [56「2026-11-27 #321」](../knowledge-base/56-fd2-remake-sdd.md#2026-11-27-321-零旗標主攻對非零旗標反擊的背景層)。

## 建置與驗證範圍

三平台引擎由來源提交 `45a98417`（#321 修正本身是 `71671cf1`，測試修正 `27d279c4`）在本機 Docker 建置，方式同 v.1.1.11，見[打包文件 §4.4](../knowledge-base/41-packaging.md#44-本機-osxcross-建置使用者2026-11-13定案)。

| 平台 | 已驗證 |
|---|---|
| Linux | 引擎包與完整包在 Xvfb 下自檢；完整包開場受控截圖 |
| Windows | 引擎包與完整包在 Wine 10 下自檢；完整包開場受控截圖 |
| macOS 通用版 | 只做靜態檢查：雙架構、arm64 簽章、只連結系統框架、最低 macOS 11.0 |

三包各 54581 份素材已獨立解包逐檔核對。Linux 與 Wine 的開場截圖相同，也與 v.1.1.16 相同（SHA-256 前綴 `affb593a`）。

修正本身的驗證：
- 第 22、25 章以同一份 dosgolem 原版收據、同一個判定器各跑 Rust 與 Go，結果相同。整章重播第 22 章 45 筆、存檔與原版逐位元組相同；第 25 章 41 筆，存檔只差政策 `ch25-opaque-20261016` 已揭露的 9 byte。兩章 #321 樣本走過原本會停住的那次反擊，行為閘門通過。詳見 [56「2026-11-27 #321」的驗收表](../knowledge-base/56-fd2-remake-sdd.md#2026-11-27-321-零旗標主攻對非零旗標反擊的背景層)。
- Go 預設全套 21 個套件 0 項失敗。這輪開始時的 23 項既有失敗（`cmd/fd2` 22 項含子測試、字串盤點 1 項）已全部修正，生產碼沒有改：測試期望值跟上已確認的 HD1 設計、缺 HD 輸入時改為略過、字串盤點補分類。需要私人 HD 素材包的測試另外帶輸入個別跑，全部通過。
- Rust fd2-game 463 項通過。

macOS 版在 Linux 上無法執行，沒有任何執行證據；Windows 的自檢在 Wine 執行，不等於原生 Windows。Windows、macOS 未簽署，macOS 未公證，首次開啟需右鍵選「打開」。
