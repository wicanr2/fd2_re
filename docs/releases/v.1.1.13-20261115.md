# v.1.1.13-20261115 發行說明

本版縮短切到 HD 的等待時間：按 F2 或 F11 第一次切到 HD，以及設定已存成 HD 時的啟動。三平台完整版以新引擎重新打包，素材與 `v.1.1.12-20261114` 相同。

Go 版自 `v.1.1.11` 起凍結，改寫主線是 Rust 版。本版是使用者 2026-11-15 同意的第二次例外，只含這項修正，之後照舊凍結。

## 本次修正

| 項目 | v.1.1.12 | 本版 |
|---|---|---|
| 第一次按 F2 到切換完成 | 217～235 秒 | 31～55 秒 |
| 第一次按 F11 到切換完成 | 220～226 秒 | 41～57 秒 |
| 設定存成 HD 時，啟動到可操作 | 117～142 秒，視窗出現前沒有任何畫面 | 3.7～6.3 秒 |
| 設定存成 HD 時，啟動到 HD 套用 | 117～142 秒 | 27～47 秒 |
| 切換期間 heap 高峰 | 3.4～3.6 GiB | 2.4～3.0 GiB |

以上以真實 HD 包在 Docker（4 核心、8 GB）下量測，主機同時有其他工作，所以列多輪的範圍。

- 載入時間有 64% 花在戰鬥 HD 動畫幀：舊版載入時把它們全部解碼一次只為了檢查透明度，第一次進戰鬥時又解碼一次。本版載入時只核對檔案、SHA-256 與圖片尺寸，透明度改在第一次用到時檢查。缺檔或雜湊不符仍整包拒收。
- 開場、地形、天空之鑰、戰鬥背景四類素材分開同時載入，最多三條。
- 設定存成 HD 時，啟動先以原版畫面進入，顯示「HD 主題素材載入中（百分比）」，載完後自動切換。載入期間存設定會保留 HD。
- 行為改變：設定為 HD 但 HD 包載入失敗時，舊版停在錯誤畫面；本版留在原版畫面並顯示「現代主題不可用：…」，設定仍保留 HD。某一組戰鬥 HD 畫格在第一次使用時沒通過檢查，該組改用原版畫格並提示一次。

## 建置與驗證範圍

三平台引擎由來源提交 `8b57cea6` 在本機 Docker 建置，方式同 v.1.1.11，見[打包文件 §4.4](../knowledge-base/41-packaging.md#44-本機-osxcross-建置使用者2026-11-13定案)。

| 平台 | 已驗證 |
|---|---|
| Linux | 引擎包與完整包在 Xvfb 下自檢；完整包開場受控截圖 |
| Windows | 引擎包與完整包在 Wine 10 下自檢；完整包開場受控截圖 |
| macOS 通用版 | 只做靜態檢查：雙架構、arm64 簽章、只連結系統框架、最低 macOS 11.0 |

三包素材已獨立解包逐檔核對，素材清單與 v.1.1.12 逐位元組相同。Linux 與 Wine 的開場截圖相同，也與 v.1.1.12 的截圖相同（SHA-256 前綴 `affb593a`）。

修正本身的驗證在重製端：
- 修正前後載入同一份 HD 包，主題內容雜湊相同。
- 正式包的 287 筆、2526 格戰鬥資源都通過延後檢查。
- 以真實 HD 包跑既有的 11 項完整主題測試，全部通過。
- `cmd/fd2` 全套測試的失敗從 22 項變成 19 項，是修正前名單的子集，皆為測試環境缺 HD 素材的既有失敗。

macOS 版在 Linux 上無法執行，沒有任何執行證據；Windows 的自檢在 Wine 執行，不等於原生 Windows。Windows、macOS 未簽署，macOS 未公證，首次開啟需右鍵選「打開」。
